49. Image Carousel

Prev/next arrows, dot indicators, autoplay. One number of state, everything else derived.

The ask

Interviewer "Build an image carousel. Arrows to go back and forward, dots showing which slide you're on, and it should auto-advance every 3 seconds."

One slide visible at a time. Clicking, or a timer, changes which one.

What we're building

Slides here are coloured blocks with a caption — in the real thing they'd be <img>. Styling isn't scored; logic and layout are.

It should:

  • Show exactly one slide at a time.
  • Arrows move back / forward.
  • Wrap around at both ends.
  • Dots show and set the current slide.
  • Auto-advance on a timer.
  • Pause on hover and focus.

The mental model

Don't move slides around. Lay all of them in a flex row that's wider than the screen, put that row inside a fixed-width box with overflow:hidden — the window — and slide the row left by whole windows.

Green border = the overflow:hidden window. The row never changes; only its transform does.

The formula translateX(-index * 100%). Add a CSS transition on transform and you get the slide animation for free.

The shape of the state

const [index, setIndex] = useState(0); // which slide is showing. That's it.
const [paused, setPaused] = useState(false); // only if autoplay is asked for

const n = images.length;
// derived, never stored:
// offset  = -index * 100%
// dots    = images.map((_, i) => i === index)

One source of truth — derive the rest. If you store a separate activeDot or offset, they'll drift apart. Everything visible is a function of index.

Build it in layers

In an interview, build L1 and L2 first, out loud, then ask "want me to add autoplay?"

L1 Static — just the track

No state. Prove the window + row layout works.

<div className="window">              // overflow:hidden; width:100%
  <div className="track">             // display:flex
    {images.map(src => (
      <img key={src} src={src} className="slide" />   // flex:0 0 100%
    ))}
  </div>
</div>

L2 Arrows + wrapping

Add index, move the track, wrap at both ends.

const [index, setIndex] = useState(0);
const n = images.length;

const next = () => setIndex(i => (i + 1) % n);
const prev = () => setIndex(i => (i - 1 + n) % n);  // the + n matters!

<div className="track" style={{ transform: `translateX(-${index * 100}%)` }}>
The off-by-one everyone gets wrong (0 - 1) % 4 is -1 in JS, not 3 — % is remainder, not modulo, and it keeps the sign. Adding n first keeps it positive: (0 - 1 + 4) % 4 === 3. ✅

L3 Dots

Derived from the same index. They read it and they set it.

{images.map((_, i) => (
  <button key={i} onClick={() => setIndex(i)}
    className={i === index ? "dot on" : "dot"}
    aria-label={`Go to slide ${i + 1}`}
    aria-current={i === index} />
))}

L4 Autoplay + pause

One interval, created in an effect, cleared on the way out.

useEffect(() => {
  if (paused) return;                       // no timer at all while paused
  const id = setInterval(next, 3000);
  return () => clearInterval(id);           // cleanup — or you stack timers
}, [paused, n]);

<div onMouseEnter={() => setPaused(true)}
     onMouseLeave={() => setPaused(false)}
     onFocus={() => setPaused(true)}
     onBlur={() => setPaused(false)}>

next uses the updater form setIndex(i => …), so the interval never needs to see a fresh index — it can't go stale.

The whole thing

import { useState, useEffect } from "react";

export default function Carousel({ images, interval = 3000 }) {
  const [index, setIndex] = useState(0);
  const [paused, setPaused] = useState(false);
  const n = images.length;

  const next = () => setIndex(i => (i + 1) % n);
  const prev = () => setIndex(i => (i - 1 + n) % n);

  useEffect(() => {
    if (paused || n <= 1) return;
    const id = setInterval(() => setIndex(i => (i + 1) % n), interval);
    return () => clearInterval(id);
  }, [paused, n, interval]);

  if (!n) return null;

  return (
    <div className="carousel"
      onMouseEnter={() => setPaused(true)} onMouseLeave={() => setPaused(false)}
      onFocus={() => setPaused(true)} onBlur={() => setPaused(false)}
      role="region" aria-roledescription="carousel" aria-label="Photos">

      <div className="window">
        <div className="track"
          style={{ transform: `translateX(-${index * 100}%)` }}>
          {images.map((img, i) => (
            <img key={img.src} src={img.src} alt={img.alt}
              className="slide" aria-hidden={i !== index} />
          ))}
        </div>
      </div>

      <button className="arrow left" onClick={prev} aria-label="Previous slide">‹</button>
      <button className="arrow right" onClick={next} aria-label="Next slide">›</button>

      <div className="dots">
        {images.map((_, i) => (
          <button key={i} onClick={() => setIndex(i)}
            className={i === index ? "dot on" : "dot"}
            aria-label={`Go to slide ${i + 1}`} aria-current={i === index} />
        ))}
      </div>
    </div>
  );
}

CSS in three lines: .window{overflow:hidden}, .track{display:flex;transition:transform .4s ease}, .slide{flex:0 0 100%}.

Gotchas

(index - 1) % n for prev. Gives -1 at slide 0 and the track flies off-screen. Always (index - 1 + n) % n.
No clearInterval. Every re-run of the effect adds a timer; the carousel speeds up and keeps running after unmount. Always return the cleanup.
Reading index inside setInterval. The closure captures the first value and the slide sticks at 1. Use the updater form setIndex(i => …).
A second state for the dots. Two sources of truth drift. Derive dots from index.
Divs for arrows and dots. Not focusable, not announced. Use <button> with an aria-label.

If they push

"Add keyboard arrows." Put tabIndex={0} on the container and handle onKeyDown: ArrowLeft → prev, ArrowRight → next. Also pause autoplay while focused.
"Make it swipeable." Record e.touches[0].clientX on touchstart, compare on touchend. Past a ~50px threshold, call next or prev; below it, snap back. 
const start = useRef(0);
onTouchStart={e => (start.current = e.touches[0].clientX)}
onTouchEnd={e => {
  const dx = e.changedTouches[0].clientX - start.current;
  if (dx < -50) next(); else if (dx > 50) prev();
}}
"Don't flash a blank slide." All slides are already in the DOM, so the browser loads them. To be explicit, preload the next one: new Image().src = images[(index + 1) % n].src in an effect. Add loading="lazy" only if there are many.
"Infinite loop with no jump back." Wrapping from 3 → 0 rewinds the track visibly. Clone the last slide before the first and the first after the last, animate into the clone, then transition:none + snap to the real index on transitionend. Say the trade-off: real infinite scroll costs clones and a transition-disabling step.
"Someone gets motion sick." Wrap the transition in @media (prefers-reduced-motion: no-preference) so it cuts instead of sliding, and don't autoplay for those users.

Say this out loud

  • "There's really only one piece of state here — the current index. Dots and the transform are both derived from it."
  • "I'll lay the slides out in a flex row inside an overflow-hidden window and just translate the row."
  • "Going backwards I add n before the modulo, because JS % keeps the sign and would give me −1 at slide zero."
  • "The interval uses the updater form so it can't capture a stale index, and I clear it in the effect cleanup."
  • "Autoplay pauses on hover and on focus — otherwise it moves out from under a keyboard user."
  • "Arrows and dots are real buttons with labels, and I'd respect prefers-reduced-motion for the slide animation."
