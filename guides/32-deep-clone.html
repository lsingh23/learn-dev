Implementing deepClone

You spread an object, feel safe, and then mutate the copy — and the original changes too. Here's why, and the ten lines that fix it.

The problem

Here's a user object with something nested inside it. We spread it into a copy, change the copy, and check the original:

❌ Looks like a copy. Isn't.
const original = {
  name: 'Ada',
  address: { city: 'London' },
};

const copy = { ...original };
copy.address.city = 'Paris';

console.log(original.address.city);  // → 'Paris'  😱

We never touched original. But it changed.

Here's the whole reason. A variable holding an object doesn't hold the object — it holds an address pointing at it, somewhere in memory. Spreading copies each property's value across, and for address that value is the address, not the nested object. So both objects now point at the same inner object. Primitives (numbers, strings, booleans) don't have this problem, because the value is the whole thing:

copy.name = 'Grace';
console.log(original.name);  // → 'Ada'  ✅ strings copy by value

That's a shallow copy: one level deep, everything below shared. A deep copy walks all the way down and rebuilds every nested object, so the two trees share nothing.

The two cheap answers

Before writing anything by hand, know these two — an interviewer will ask about both, and in real code you'll usually reach for one of them.

1. JSON.parse(JSON.stringify(obj))

Serialize to a string, parse it back. A brand new tree, one line, no dependencies. For plain data that came out of an API — objects, arrays, strings, numbers, booleans, null — this is genuinely fine, and pretending otherwise is posturing.

But JSON only knows about JSON. Everything else gets quietly mangled:

❌ What JSON round-tripping destroys
const data = {
  createdAt: new Date(),
  onSave: () => {},
  tags: new Set(['a']),
  nickname: undefined,
  score: NaN,
};

JSON.parse(JSON.stringify(data));
// → {
//     createdAt: '2025-09-02T10:00:00.000Z',  // a string now
//     tags: {},                                // Set emptied out
//     score: null                              // NaN → null
//   }
// onSave and nickname just... aren't there.

The short list: functions and undefined vanish, Date becomes a string, Map/Set/RegExp become {}, NaN and Infinity become null, and a circular reference throws outright. Notice that almost all of those fail silently — you find out in production.

2. structuredClone(obj)

The built-in, available in every modern browser and Node 17+. It handles Dates, Maps, Sets, RegExps, typed arrays, and — the good bit — circular references, correctly.

const deep = structuredClone(original);

Two things it won't do: it throws on functions (a DataCloneError), and it drops class prototypes — clone a User instance and you get a plain object with the right fields and none of the methods.

In an interview

Say this out loud before you start coding: "In real code I'd use structuredClone — it's built in and handles Dates, Maps and cycles. But let me write one by hand." It costs you five seconds and shows you know the platform. Then write it anyway — that's the actual question.

Building it recursively

The shape of the problem is recursive, so the function is too. Two questions: when do we stop, and what do we do when we don't?

Stop when the value isn't an object. Primitives copy by value already, so we just hand them back. And typeof null === 'object' — a famous JS wart — so null has to be excluded explicitly or we'd try to iterate it.

Step 1 — the base case
function deepClone(value) {
  if (value === null || typeof value !== 'object') {
    return value;                    // 👈 primitives, null, functions: as-is
  }
  // ...it's an object. Rebuild it.
}

Now the recursive case. Arrays and plain objects need different empty containers, and Array.isArray is how you tell them apart (typeof [] is 'object', so that's no help). Then we copy each key across — but instead of assigning the value, we assign deepClone of the value.

✅ Step 2 — the version to write in an interview
function deepClone(value) {
  if (value === null || typeof value !== 'object') return value;

  const result = Array.isArray(value) ? [] : {};   // 👈 right container

  for (const key of Object.keys(value)) {
    result[key] = deepClone(value[key]);           // 👈 the whole idea
  }

  return result;
}

That's it. Ten lines, and it correctly handles arbitrarily nested objects and arrays. Trace the user object: name is a string so it returns immediately; address is an object, so we recurse, build a fresh {}, and copy city into it. Two separate trees.

Say the recursion out loud as you write it — "if it's a primitive I'm done, otherwise make an empty one of the same kind and deep-clone every value into it" — because that sentence is what's being graded.

Dates and regexes

Both are objects, so our function currently turns new Date() into {} — they have no enumerable own keys. Two lines, above the container:

if (value instanceof Date) return new Date(value);
if (value instanceof RegExp) return new RegExp(value.source, value.flags);

Circular references

Now the follow-up that separates candidates. An object can point at itself:

const user = { name: 'Ada' };
user.self = user;         // 👈 perfectly legal

deepClone(user);          // → RangeError: Maximum call stack size exceeded

We clone user, hit self, recurse into user again, hit self... forever. The fix: keep a map of original → its clone. At the top of every call, check whether we've already cloned this exact object; if so, return the clone we made before instead of building another one.

The subtle part is the order. You have to register the clone in the map before recursing into the children — otherwise the recursion reaches self before the entry exists and loops anyway.

✅ The full version
function deepClone(value, seen = new WeakMap()) {
  if (value === null || typeof value !== 'object') return value;
  if (value instanceof Date) return new Date(value);
  if (value instanceof RegExp) return new RegExp(value.source, value.flags);

  if (seen.has(value)) return seen.get(value);      // 👈 been here before

  const result = Array.isArray(value) ? [] : {};
  seen.set(value, result);                          // 👈 register BEFORE recursing

  for (const key of Object.keys(value)) {
    result[key] = deepClone(value[key], seen);      // 👈 pass the map down
  }

  return result;
}

As a bonus this also preserves shared references. If two properties point at the same object, the clone's two properties point at the same clone — the shape of the graph survives, not just the data.

Wait — what about Maps, Sets, and symbol keys?

Each is a small addition: new Map([...value].map(([k, v]) => [deepClone(k), deepClone(v)])) and similar for Set; Reflect.ownKeys instead of Object.keys picks up symbols. Mention them as "I'd add branches for those"; don't write them unprompted. Getters, non-enumerable properties and property descriptors are the same story — name them, move on. Interviewers read a candidate who tries to handle every type as someone who can't scope.

The interview layer

How it gets asked

  • "Implement a deep clone function."
  • "What's the difference between a shallow and a deep copy?"
  • "This code mutates state it shouldn't — why?" (the same question, in bug form)
🗣 Model answer

"Objects are held by reference, so spreading only copies the top level — nested objects are still shared, and mutating one shows up in both. A deep clone rebuilds every level. In production I'd use structuredClone, which handles Dates, Maps and circular refs; I'd avoid the JSON round-trip because it silently drops functions and turns Dates into strings. By hand it's a recursion: return primitives as-is, otherwise make an empty array or object and deep-clone each value into it. Then I'd add a WeakMap of already-cloned objects so circular references don't blow the stack."

That lands because it's ordered by what matters: the why, then the real-world tool, then the implementation, then the edge case — instead of diving straight into a for-loop.

Follow-ups

"Why not just JSON.parse(JSON.stringify())?"

For plain API data, honestly, you can. But it drops functions and undefined, turns Dates into strings, flattens Maps and Sets to {}, converts NaN to null, and throws on cycles. All of that except the throw is silent, so bugs surface far from the cause. It's also slow on big objects — you're building an entire string in memory.

"How do you handle circular references?"

A seen map from original object to its clone, threaded through the recursion. Check it first thing; if the object's in there, return the existing clone. Crucially, add the entry before recursing into children, or you never break the loop.

"Why a WeakMap and not a Map?"

A WeakMap holds its keys weakly, so entries don't keep the source objects alive — with a regular Map you'd pin every object you visited in memory for as long as the map lived. Here the map is created per top-level call and dies with it, so it's not dramatic, but it's the right default and the interviewer is checking whether you know the difference at all.

"Does your clone preserve the prototype? Class instances?"

No. {} gives you a plain object, so a User instance comes back with the right fields and no methods, and instanceof User is false. The fix is one line: Object.create(Object.getPrototypeOf(value)) instead of {} — though that still skips the constructor, which matters if it does real work.

"Do you actually need a deep clone here?"

Usually no, and this is the senior answer. Cloning an entire state tree to change one field is wasteful. Prefer an immutable update that copies only the path you're touching: { ...state, user: { ...state.user, city: 'Paris' } } — everything else is shared, which is safe because nothing mutates it. That's exactly what Redux reducers do by hand and what Immer does for you behind a mutable-looking API. Reach for a deep clone when you're handed an object from outside your control and genuinely need to own it.

"Is deep cloning expensive?"

It's O(n) in the total number of nodes, plus an allocation per object, plus recursion depth on the call stack — a deeply nested structure can overflow it. On a large tree in a hot path (a render, a scroll handler) it's very noticeable. Structural sharing avoids the cost entirely.

Traps

  • Forgetting null. typeof null === 'object', so it falls into the object branch and you return {}.
  • Using for...in without a guard. It walks inherited enumerable properties too. Object.keys avoids the question.
  • Registering the clone after the loop. The circular-ref code compiles and still overflows.
  • Calling the spread operator a deep copy. Instant ding.

Cheat sheet

  • Shallow — { ...obj }, Object.assign, slice: one level; nested objects still shared.
  • Why — objects are held by reference; copying the property copies the arrow.
  • JSON round-trip — fine for plain data; kills functions, undefined, Dates, Map/Set, NaN; throws on cycles.
  • structuredClone — the real-world answer; handles Dates, Maps, Sets, cycles. Throws on functions, loses prototypes.
  • By hand — primitive → return it; else new container + recurse per key.
  • Cycles — WeakMap of original → clone, registered before recursing.
  • Senior move — you usually want an immutable update of one path, not a clone of everything.
function deepClone(value, seen = new WeakMap()) {
  if (value === null || typeof value !== 'object') return value;
  if (value instanceof Date) return new Date(value);
  if (value instanceof RegExp) return new RegExp(value.source, value.flags);
  if (seen.has(value)) return seen.get(value);

  const result = Array.isArray(value) ? [] : {};
  seen.set(value, result);

  for (const key of Object.keys(value)) {
    result[key] = deepClone(value[key], seen);
  }
  return result;
}
