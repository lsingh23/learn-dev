36. Star Rating

Two pieces of state, one derived number. The whole question lives in that trick.

The ask

Interviewer "Build a star rating component. Hovering previews a rating, clicking commits it, and the number of stars should be configurable."

Stars light up under your mouse. Click freezes that value. Move away, it snaps back.

What we're building

Resting — rating = 3
★★★ ★★
12345

filled = value ≤ rating  ·  the numbers are index + 1

Hovering star 5 — rating still 3
★★★ ★★
1234 ↑
preview only — nothing saved yet
Mouse leaves — back to 3
★★★ ★★

It should:

  • Render count stars (default 5).
  • Fill stars up to the hovered one.
  • Click commits that number.
  • Mouse leave restores the committed value.
  • Work with keyboard and a screen reader.
  • Report changes to the parent.

The mental model

Two numbers, not one. rating is what the user chose. hover is what they're pointing at right now, or 0 for nothing. What you paint is hover || rating — hover wins while it exists.

Why || works 0 is falsy, so "not hovering" falls straight through to the committed rating. No if needed.

The shape of the state

const [rating, setRating] = useState(0); // what the user picked. 0 = none
const [hover, setHover]   = useState(0); // what they're pointing at. 0 = nothing

const display = hover || rating;         // derived — never stored

Rule of thumb: store what you're told, derive what you draw. A third filledStars array would be a bug waiting to happen.

Build it in layers

In an interview, build L1 and L2 first, out loud, then ask "want me to add hover preview and keyboard support?"

L1 Just draw N stars

No state. Prove the loop works.

function StarRating({ count = 5 }) {
  return (
    <div>
      {Array.from({ length: count }, (_, i) => (
        <span key={i}>★</span>   // i = 0..count-1
      ))}
    </div>
  );
}
Why i + 1 is the value Indexes start at 0, ratings start at 1. Star at index 0 means "1 star". Compute const value = i + 1 once at the top of the loop and use it everywhere.

L2 Click to set

One state. Fill everything up to it.

const [rating, setRating] = useState(0);

{Array.from({ length: count }, (_, i) => {
  const value = i + 1;
  return (
    <span key={value}
      onClick={() => setRating(value)}
      style={{ color: value <= rating ? "#f5a623" : "#ccc" }}>★</span>
  );
})}

L3 Hover preview

Second state. Set it on enter, clear it on leave.

const [hover, setHover] = useState(0);
const display = hover || rating;

<div onMouseLeave={() => setHover(0)}>      // reset on the container
  ...
  <span onMouseEnter={() => setHover(value)}
        style={{ color: value <= display ? "#f5a623" : "#ccc" }}>★</span>
</div>
Reset on the container, not each star Per-star onMouseLeave flickers as you slide between stars — it fires before the next onMouseEnter.

L4 Buttons, labels, controlled option

Real <button>s so Tab and Enter work for free. And let the parent own the value.

function StarRating({ count = 5, value, onChange }) {
  const [inner, setInner] = useState(0);
  const isControlled = value !== undefined;      // parent drives it?
  const rating = isControlled ? value : inner;

  const set = (v) => {
    if (!isControlled) setInner(v);              // only own state if uncontrolled
    onChange?.(v);                               // always tell the parent
  };
}
Controlled vs uncontrolled, in one line If the value prop exists, the parent is the source of truth and you only call onChange. If it doesn't, you keep your own state. Same as <input>.

The whole thing

import { useState } from "react";

export default function StarRating({ count = 5, value, onChange, label = "Rating" }) {
  const [inner, setInner] = useState(0);
  const [hover, setHover] = useState(0);

  const isControlled = value !== undefined;
  const rating  = isControlled ? value : inner;
  const display = hover || rating;

  const set = (v) => {
    if (!isControlled) setInner(v);
    onChange?.(v);
  };

  return (
    <div role="radiogroup" aria-label={label}
         onMouseLeave={() => setHover(0)}
         style={{ display: "flex", gap: 4 }}>
      {Array.from({ length: count }, (_, i) => {
        const v = i + 1;
        return (
          <button
            key={v}
            type="button"
            role="radio"
            aria-checked={v === rating}
            aria-label={`${v} star${v > 1 ? "s" : ""}`}
            tabIndex={v === rating || (rating === 0 && v === 1) ? 0 : -1}
            onClick={() => set(v)}
            onMouseEnter={() => setHover(v)}
            onFocus={() => setHover(v)}
            onBlur={() => setHover(0)}
            onKeyDown={(e) => {
              if (e.key === "ArrowRight" || e.key === "ArrowUp") set(Math.min(rating + 1, count));
              if (e.key === "ArrowLeft"  || e.key === "ArrowDown") set(Math.max(rating - 1, 1));
            }}
            style={{
              background: "none", border: "none", padding: 0, cursor: "pointer",
              fontSize: 28, lineHeight: 1,
              color: v <= display ? "#f5a623" : "#d6d3cc",
            }}
          >
            ★
          </button>
        );
      })}
    </div>
  );
}

Inline styles keep it one file — swap for CSS in real code. Styling isn't what's being scored here.

Gotchas

Using the index as the rating. i is 0-based; the first star must mean 1. Always const v = i + 1.
Forgetting to reset hover. Without onMouseLeave the preview sticks after the mouse is gone and the component lies about its value.
Storing the display value in state. A third useState for "what's shown" desyncs instantly. It's derived: hover || rating.
Divs with onClick. No focus, no Enter key, no announcement. Use <button> — the free accessibility is worth the two extra style resets.
Mixing controlled and uncontrolled. Calling setInner when a value prop exists gives you two owners fighting. Guard it.

If they push

"Add half stars." Split each star into two half-width hit zones, left = v - 0.5, right = v. Render with a clipped overlay: 
// grey star underneath, gold star clipped on top
<span style={{ position: "relative" }}>
  <span style={{ color: "#d6d3cc" }}>★</span>
  <span style={{ position: "absolute", left: 0, overflow: "hidden",
                 width: `${Math.min(Math.max(display - i, 0), 1) * 100}%`,
                 color: "#f5a623" }}>★</span>
</span>
"Make it keyboard accessible." Radio-group pattern: one tab stop for the whole group (tabIndex 0 on the selected star, -1 on the rest), arrows move the value, and onFocus mirrors hover so the preview follows the keyboard.
"Let the user clear it." Clicking the current rating again sets it to 0: set(v === rating ? 0 : v). Mention it — it's a real product decision, so ask first.
"Make it read-only for displaying an average." A readOnly prop: skip the handlers, render <span>s instead of buttons, and put one aria-label="4.2 out of 5" on the wrapper.
"1000 of these in a list." They're cheap, but React.memo the component and give the parent a stable onChange via useCallback so one row's hover doesn't re-render the list.

Say this out loud

  • "I'll keep two pieces of state — the committed rating and a temporary hover — and derive what I render from both."
  • "Hover is 0 when nothing's hovered, so hover || rating falls back for free."
  • "Star index i maps to value i + 1, so the first star is 1, not 0."
  • "The mouse-leave reset goes on the container — per-star it flickers between stars."
  • "I'll use buttons in a radiogroup so it's keyboard and screen-reader usable without extra work."
  • "I can make it controlled by accepting value and onChange — want me to do that now?"
