45. Infinite Scroll

Load the next page when the bottom of the list comes into view.

The ask

Interviewer "Render a feed. When the user scrolls near the bottom, fetch the next page and append it. No pagination buttons."

Plain English: watch the bottom of the list. When it's visible, ask for more and add it to what's already there.

What we're building

Feed — scrolled to the bottom
↻ loading page 3…
SENTINEL DIV — 1px tall, invisible to the user
blue box = viewport (what you can see) red dashes = bottom edge green = sentinel crossing it → fetch

It should:

  • Render items as one growing list.
  • Fetch the next page near the bottom.
  • Append, never replace.
  • Show a loading row while fetching.
  • Fetch each page exactly once.
  • Stop cleanly at "no more items".

Styling barely matters here. The scoring is all in the guards.

The mental model

Put an empty marker div after the last item. Ask the browser to tell you when that marker enters the screen. That's your "load more" trigger — no scroll maths.

The whole trick The browser already knows what's on screen. IntersectionObserver — a watcher that fires when an element enters view — just tells you. You never read scroll positions.

The old way, if they ask for the pre-observer version — fire when you're within 100px of the end:

// on the scroll event of the scrolling element (or window)
const { scrollTop, clientHeight, scrollHeight } = el;
if (scrollTop + clientHeight >= scrollHeight - 100) loadMore();
// how far you've scrolled + how tall the window is = where the bottom edge sits
// scrollHeight = total content height. Equal-ish → you're at the end.

Works, but it runs on every scroll frame and needs throttling. Say that, then use the observer.

The shape of the state

const [items, setItems]   = useState([]);   // everything loaded so far, appended
const [page, setPage]     = useState(1);    // which page to fetch next — the cursor
const [loading, setLoading] = useState(false); // guard: a fetch is in flight
const [hasMore, setHasMore] = useState(true);  // guard: server still has pages
const [error, setError]   = useState(null);  // so the user can retry

Rule of thumb: one source of truth. items.length is derived, so don't store a count. page is the only thing that decides what gets fetched — so a page can only be fetched once.

Build it in layers

In the interview Build L1 and L2 out loud, get a list appending on a button click, then say: "that's the data layer working — want me to wire it to scroll now?"

L1 Static list

The dumbest thing that renders. No state, no fetch.

function Feed() {
  const items = [{ id: 1, title: "Item 1" }, { id: 2, title: "Item 2" }];
  return (
    <ul>{items.map(i => <li key={i.id}>{i.title}</li>)}</ul>
  );
}

L2 Append on demand

A button proves the data layer. Note the functional update — add, never replace.

const [items, setItems] = useState([]);
const [page, setPage] = useState(1);

async function loadMore() {
  const res  = await fetch(`/api/items?page=${page}`);
  const data = await res.json();
  setItems(prev => [...prev, ...data.items]); // append!
  setPage(p => p + 1);
}
<button onClick={loadMore}>Load more</button>

L3 The three guards

Without these, one scroll fires five fetches and you get duplicate items.

async function loadMore() {
  if (loading || !hasMore) return;   // guard 1 + 2
  setLoading(true);
  try {
    const data = await (await fetch(`/api/items?page=${page}`)).json();
    setItems(prev => [...prev, ...data.items]);
    setPage(p => p + 1);              // guard 3: page only advances once
    setHasMore(data.items.length > 0);
  } catch (e) { setError(e); }
  finally { setLoading(false); }
}

L4 The sentinel + observer

Attach the observer with a callback ref — a function React calls with the DOM node. The sentinel unmounts while loading, so a plain useRef + useEffect can miss it.

const observer = useRef(null);

const sentinelRef = useCallback(node => {
  if (loading) return;
  if (observer.current) observer.current.disconnect(); // cleanup old one
  observer.current = new IntersectionObserver(entries => {
    if (entries[0].isIntersecting && hasMore) loadMore();
  });
  if (node) observer.current.observe(node);
}, [loading, hasMore]);

{hasMore && <div ref={sentinelRef} style={{ height: 1 }} />}

The whole thing

import { useState, useRef, useCallback, useEffect } from "react";

export default function Feed() {
  const [items, setItems]     = useState([]);
  const [page, setPage]       = useState(1);
  const [loading, setLoading] = useState(false);
  const [hasMore, setHasMore] = useState(true);
  const [error, setError]     = useState(null);
  const observer = useRef(null);

  const loadMore = useCallback(async () => {
    if (loading || !hasMore) return;
    setLoading(true); setError(null);
    try {
      const res  = await fetch(`/api/items?page=${page}&limit=20`);
      const data = await res.json();
      setItems(prev => [...prev, ...data.items]);
      setPage(p => p + 1);
      setHasMore(data.items.length > 0);
    } catch (e) {
      setError("Couldn't load more.");
    } finally {
      setLoading(false);
    }
  }, [page, loading, hasMore]);

  useEffect(() => { loadMore(); }, []); // first page

  const sentinelRef = useCallback(node => {
    if (loading) return;
    if (observer.current) observer.current.disconnect();
    observer.current = new IntersectionObserver(
      entries => { if (entries[0].isIntersecting) loadMore(); },
      { rootMargin: "200px" } // start early, feels instant
    );
    if (node) observer.current.observe(node);
  }, [loading, loadMore]);

  // unmount: stop watching
  useEffect(() => () => observer.current?.disconnect(), []);

  return (
    <ul>
      {items.map(i => <li key={i.id}>{i.title}</li>)}
      {loading  && <li aria-live="polite">Loading…</li>}
      {error    && <li>{error} <button onClick={loadMore}>Retry</button></li>}
      {!hasMore && <li>You're all caught up.</li>}
      {hasMore && !error && <li ref={sentinelRef} style={{ height: 1 }} />}
    </ul>
  );
}

Gotchas

setItems(data.items) instead of appending. The list flickers and never grows. Always setItems(prev => [...prev, ...next]).
No loading guard. The observer fires repeatedly while the sentinel sits on screen — five parallel fetches for page 3.
Never disconnecting. Old observers stay alive on unmounted nodes and leak. Disconnect before making a new one, and on unmount.
Rendering the sentinel when hasMore is false. It stays visible forever and hammers the server with empty pages.
key={index}. Indexes shift as pages append; React reuses the wrong DOM. Use the item's id.

If they push

"Now make it work with 10,000 items." DOM nodes, not fetching, become the bottleneck. Virtualise — render only the visible window (react-window/@tanstack/virtual) and drive loading from the last rendered index instead of a sentinel.
"Keep my place when I navigate back." Cache items + page + scrollY outside the component (context, or sessionStorage) and restore scroll in a layout effect after the cached items render — otherwise you scroll before the height exists.
"The fetch failed." Stop the observer (don't render the sentinel), show the error row with a Retry button that calls loadMore again. Never silently retry in a loop.
"Do it without IntersectionObserver." Scroll listener + scrollTop + clientHeight >= scrollHeight - 100, throttled to ~200ms, removed in the effect cleanup.
"How do you test it?" Stub global.IntersectionObserver with a fake that lets you manually call the callback with isIntersecting: true.

Say this out loud

  • "I'll keep one list in state and always append to it, never replace it."
  • "The bottom marker is just an empty div — the browser tells me when it's visible, so I don't do scroll maths."
  • "Three guards stop a fetch storm: is-loading, has-more, and page only advances after a success."
  • "I'll disconnect the observer before I re-attach it, and again on unmount, so nothing leaks."
  • "I'll add rootMargin so it loads slightly before the user hits the end."
  • "The loading row is aria-live so screen reader users hear that more arrived — and I'd offer a real Load-more button as a fallback."
