37. Accordion

A list of sections; click a header to expand it. The whole question is one state decision.

The ask

Interviewer "Build an accordion from this array of sections. Clicking a header expands it, clicking it again collapses it. Only one open at a time."

A list of headers. One is open. Click a header → that one opens, the old one closes.

What we're building

FAQ accordion — section 2 is open
What is your refund policy? ▸
How do I cancel? ▾
Open Settings → Billing → Cancel. Your plan stays active until the end of the period.
Do you offer student pricing? ▸
↑ each row = one object in the sections array
↑ header is a real <button> — full width, clickable
↑ chevron flips ▸ → ▾; body only renders for the open id
↑ click "How do I cancel?" again closes it — nothing is open

It should:

  • Render sections from a data array
  • Click header → expand that section
  • Click the open header → collapse it
  • Only one open at a time (default)
  • Start with all closed
  • Be keyboard + screen-reader usable
  • Switch to multi-open on request

The mental model

You are not storing "is this open" on every section. You store which one is open, once, at the top. Every header asks the same question: is my id the open one?

One source of truthOpen/closed is derived from openId. Never copy it into each item.

The shape of the state

single-open

// the id of the open section, or null
const [openId, setOpenId] = useState(null);

const isOpen = (id) => openId === id;
const toggle = (id) =>
  setOpenId(cur => cur === id ? null : id);

multi-open

// a Set of every open id
const [openIds, setOpenIds] = useState(new Set());

const isOpen = (id) => openIds.has(id);
const toggle = (id) => setOpenIds(cur => {
  const next = new Set(cur);        // copy!
  next.has(id) ? next.delete(id) : next.add(id);
  return next;
});
They will ask you to switch mid-way"Now let two be open at once." Because every header only calls isOpen(id) and toggle(id), you swap those two functions and the JSX doesn't move. Write it that way from the start and say so.

Build it in layers

In an interview, build L1 and L2 first, out loud, then ask "want me to add multi-open / animation / a11y?"

L1 Static list, no state

Map the data. Everything open. Prove the shape.

const SECTIONS = [
  { id: "a", title: "Refunds", body: "30 days, no questions." },
  { id: "b", title: "Cancel",  body: "Settings → Billing." },
];

{SECTIONS.map(s => (
  <div key={s.id}>
    <h3>{s.title}</h3>
    <p>{s.body}</p>
  </div>
))}

L2 One open at a time

Add openId. Header becomes a button. Body renders only when open.

const [openId, setOpenId] = useState(null);

{SECTIONS.map(s => {
  const open = openId === s.id;
  return (
    <div key={s.id}>
      <button onClick={() => setOpenId(open ? null : s.id)}>
        {s.title} {open ? "▾" : "▸"}
      </button>
      {open && <p>{s.body}</p>}
    </div>
  );
})}

open ? null : s.id is the whole toggle rule.

L3 Accessible header

A screen reader must know it's expandable and what it controls.

<button
  onClick={() => toggle(s.id)}
  aria-expanded={open}              // ▸ or ▾, spoken
  aria-controls={`panel-${s.id}`}   // points at the body
  id={`hd-${s.id}`}
>{s.title}</button>

<div id={`panel-${s.id}`} role="region" aria-labelledby={`hd-${s.id}`}>
  {s.body}
</div>
Free wins from <button>Tab focus, Enter/Space, focus ring. A clickable <div> gives you none of them.

L4 Multi-open, one-line swap

Same JSX. Only the state helpers change.

const [openIds, setOpenIds] = useState(new Set());
const isOpen = id => openIds.has(id);
const toggle = id => setOpenIds(cur => {
  const next = new Set(cur);
  next.has(id) ? next.delete(id) : next.add(id);
  return next;                      // new Set → React re-renders
});

The whole thing

import { useState } from "react";

const SECTIONS = [
  { id: "a", title: "What is your refund policy?", body: "30 days, no questions." },
  { id: "b", title: "How do I cancel?",            body: "Settings → Billing → Cancel." },
  { id: "c", title: "Student pricing?",            body: "Yes — 50% with a .edu email." },
];

export default function Accordion({ sections = SECTIONS, multi = false }) {
  const [openIds, setOpenIds] = useState([]);   // array of open ids

  const isOpen = (id) => openIds.includes(id);

  const toggle = (id) =>
    setOpenIds((cur) =>
      cur.includes(id)
        ? cur.filter((x) => x !== id)           // click open one → close
        : multi
        ? [...cur, id]                          // many open
        : [id]                                  // only one open
    );

  return (
    <div className="acc">
      {sections.map((s) => {
        const open = isOpen(s.id);
        return (
          <div className="acc-item" key={s.id}>
            <h3>
              <button
                id={`hd-${s.id}`}
                className="acc-hd"
                aria-expanded={open}
                aria-controls={`panel-${s.id}`}
                onClick={() => toggle(s.id)}
              >
                <span>{s.title}</span>
                <span aria-hidden="true">{open ? "▾" : "▸"}</span>
              </button>
            </h3>
            {open && (
              <div
                id={`panel-${s.id}`}
                role="region"
                aria-labelledby={`hd-${s.id}`}
                className="acc-bd"
              >
                {s.body}
              </div>
            )}
          </div>
        );
      })}
    </div>
  );
}

One multi prop covers both modes. Styling barely matters here — logic and markup are what's scored.

Gotchas

Storing isOpen on each section object Two sources of truth; closing the old one becomes a loop. Store one openId and derive.
Mutating the Set or array in place set.add(id); setOpenIds(set) — same reference, no re-render. Always build a new one.
Forgetting the "click the open one closes it" case setOpenId(s.id) alone never closes. It's open ? null : s.id.
Using the array index as the key or the id Breaks the moment sections are sorted or removed. Use a stable s.id.
A <div onClick> header Not focusable, no Enter/Space, invisible to screen readers. Use a <button>.

If they push

"Animate the open/close." {open && …} can't animate — the node isn't there. Keep the panel mounted and animate grid-template-rows: 0fr → 1fr (or max-height) with overflow:hidden. Then hide the closed panel from AT with hidden / inert.
"Conditional render or CSS hide?" Conditional render = lighter DOM, panel state resets, no animation. CSS hide = keeps scroll position and form input, animatable, but renders everything. Say the trade-off, pick render-when-open unless they want animation.
"Make it controlled." Accept openId + onChange props; fall back to internal state when openId is undefined. Same helpers, different source.
"Add arrow-key navigation." On the header, onKeyDown: ↓/↑ move focus to the next/previous header (refs array), Home/End jump to first/last. Enter and Space already work for free.
"Should one be open on load?" useState(sections[0].id). For "remember it", read from localStorage in the initialiser.

Say this out loud

  1. "I'll drive it from a sections array so it works for any data — nothing hardcoded in JSX."
  2. "The only state is which section is open. Everything else I derive."
  3. "I'll go through isOpen(id) and toggle(id), so if you want multi-open I change those two lines, not the markup."
  4. "Clicking the already-open header sets it back to null — that's the collapse case."
  5. "The header is a real button with aria-expanded and aria-controls, so keyboard and screen readers work."
  6. "I'm conditionally rendering the panel; if you want it animated I'd keep it mounted and animate the height instead."
