43. Traffic Light

Auto-cycles green → yellow → red, each with its own duration. A state-machine question in disguise.

The ask

Interviewer "Build a traffic light that cycles by itself: green for 3s, yellow for 1s, red for 4s, then repeats forever."

Three lamps. One is lit at a time. A timer moves the light on. Durations differ.

What we're building

Traffic light — currently in green
  • ← red lamp — dimmed, not active
  • ← yellow lamp — dimmed, not active
  • ← green lamp — lit, glowing index 0, 3000ms left
Pause Next → optional, only if they ask

It should:

  • Show three lamps, one lit.
  • Advance green → yellow → red.
  • Wrap back to green forever.
  • Use a different duration per colour.
  • Clear its timer on unmount.
  • Read colours/durations from config, not hardcoded.

Styling barely matters here — three circles is enough. The cycle logic is what's scored.

The mental model

It's a ring of states. You are standing on one; after its duration you step to the next; after the last you step back to the first. So: a list + a pointer.

The whole trick The colour is data, not code. A config array holds {color, ms}; state is just i. Adding a fourth phase becomes an array edit, not a rewrite.

The shape of the state

// config — not state. Lives outside the component so it's stable.
const LIGHTS = [
  { color: 'green',  ms: 3000 },
  { color: 'yellow', ms: 1000 },
  { color: 'red',    ms: 4000 },
];

const [i, setI] = useState(0);   // which light is on. ONE number.
const current = LIGHTS[i];       // derived → { color:'green', ms:3000 }

Rule of thumb: one source of truth, derive the rest. Never store isRed, isGreen, isYellow — three booleans can disagree; one index can't.

Build it in layers

In an interview Build L1 and L2 out loud, get it cycling, then ask: "want me to add pause and manual advance?"

L1 Three static lamps

Dumbest thing that renders. No state.

<div className="pole">
  {LIGHTS.map(l => (
    <div key={l.color} className="lamp"
         style={{ background: l.color }} />
  ))}
</div>

L2 Light exactly one, on a timer

Opacity carries "on". One setTimeout, keyed on i.

const [i, setI] = useState(0);

useEffect(() => {
  const id = setTimeout(
    () => setI(p => (p + 1) % LIGHTS.length),  // wrap
    LIGHTS[i].ms                                // this light's own duration
  );
  return () => clearTimeout(id);   // cleanup, every time
}, [i]);

// in JSX: opacity: idx === i ? 1 : 0.25

i changes → effect re-runs → new timeout with the next duration. That's the engine.

L3 Pause / resume

One boolean. When paused, schedule nothing.

const [running, setRunning] = useState(true);

useEffect(() => {
  if (!running) return;                // no timer while paused
  const id = setTimeout(next, LIGHTS[i].ms);
  return () => clearTimeout(id);
}, [i, running]);

L4 Manual advance + configurable

The same next the timer uses. Config comes in as a prop.

function TrafficLight({ lights = LIGHTS }) { ... }

const next = () => setI(p => (p + 1) % lights.length);

<button onClick={next}>Next</button>   // clicking also resets
// the timer, because i changed → effect re-runs

The whole thing

import { useState, useEffect } from 'react';

const LIGHTS = [
  { color: 'green',  ms: 3000 },
  { color: 'yellow', ms: 1000 },
  { color: 'red',    ms: 4000 },
];

export default function TrafficLight({ lights = LIGHTS }) {
  const [i, setI] = useState(0);
  const [running, setRunning] = useState(true);

  const next = () => setI(p => (p + 1) % lights.length);

  useEffect(() => {
    if (!running) return;
    const id = setTimeout(next, lights[i].ms);
    return () => clearTimeout(id);
  }, [i, running, lights]);

  return (
    <div>
      <div className="pole"
           role="status"
           aria-label={`Traffic light: ${lights[i].color}`}>
        {lights.map((l, idx) => (
          <div
            key={l.color}
            className="lamp"
            style={{
              background: l.color,
              opacity: idx === i ? 1 : 0.25,
            }}
          />
        ))}
      </div>

      <button onClick={() => setRunning(r => !r)}>
        {running ? 'Pause' : 'Resume'}
      </button>
      <button onClick={next}>Next</button>
    </div>
  );
}

Gotchas

Hardcoding three if-statements. if (color === 'green') setColor('yellow')… works and loses points — it can't do per-light durations cleanly and can't be extended. Show the config array instead.
Using setInterval. An interval has one fixed period; your lights don't. setTimeout re-scheduled per state is the correct tool.
No clearTimeout in the cleanup. Timers pile up, the light skips ahead, and React warns on unmount. Always return () => clearTimeout(id).
setI(i + 1) instead of setI(p => p + 1). The callback captured a stale i. Use the updater form.
Defining LIGHTS inside the component. A new array each render → if it's in the dep array, the effect restarts every render. Hoist it out, or useMemo it.

If they push

"Make the durations configurable." Already done — lights is a prop. <TrafficLight lights={[{color:'red',ms:500}]} /> just works.
"Add a countdown showing seconds left." Second piece of state ticking every 1000ms, reset to lights[i].ms/1000 when i changes. Keep it in a separate effect.
"Pause should resume mid-light, not restart it." Store remaining in a ref — a box that survives re-renders — record Date.now() when the timer starts, subtract on pause, schedule the leftover on resume.
"Two lights at a crossroads, always opposite." One state machine, two views. Second light renders lights[(i + offset) % lights.length]. Never two independent timers.
"Is it accessible?" Colour alone isn't a signal. Add the colour name as text, and role="status" so screen readers announce changes.

Say this out loud

  1. "This is a state machine, so I'll put the phases in a config array and keep a single index in state."
  2. "Durations differ per light, so setTimeout re-scheduled per state, not setInterval."
  3. "The effect depends on the index — when the index changes it tears down the old timer and schedules the next duration."
  4. "I'm returning a cleanup so nothing fires after unmount."
  5. "Updater form for the index so I don't read a stale value from the closure."
  6. "Colour isn't accessible on its own — I'd add a text label and role=status."
