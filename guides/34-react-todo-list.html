34. Todo List

The warm-up round. It scores array state, immutable updates, keys and derived data.

The ask

Interviewer “Build a todo list. I should be able to add items, tick them off, delete them, and switch between All / Active / Done.”

One array of todos. Everything on screen is drawn from it.

What we're building

Todo list — the whole UI
Buy milk| Add
↑ controlled input — value comes from state
All Active Done
↑ one filter string, not three lists
Water the plants×
✓Book flights×
Call the dentist×

2 left3 total

styling barely matters here — they're watching your state.

It should:

  • Add a todo from the input
  • Clear the input after adding
  • Ignore empty / whitespace-only input
  • Toggle any todo done or not
  • Delete any todo
  • Show All, Active, or Done
  • Count how many are left

The mental model

Two pieces of state, one screen. The list is the truth; the filter is a lens you look through. You never store a filtered list — you compute it on every render.

Rule of thumb If you can compute it from state, don't store it. Filtered list, “items left”, “all done?” — all derived.

The shape of the state

// the truth: one flat array, newest last
const [todos, setTodos] = useState([]);
//   { id: 1712, text: "Buy milk", done: false }
//     id   -> stable key, survives reorder/delete
//     text -> what to show
//     done -> ticked or not

// what's typed right now (controlled input)
const [text, setText] = useState("");

// which lens: "all" | "active" | "done"
const [filter, setFilter] = useState("all");

Three tiny pieces. Anything else on screen is a .filter() away.

Build it in layers

In the interview Build L1 and L2 out loud first — a working add. Then say “that's add working; want toggle and delete next, or filtering?”

L1 Static markup, no state

Prove the layout renders before any logic exists.

function App() {
  return (
    <div>
      <form><input placeholder="Add a todo" /><button>Add</button></form>
      <ul>
        <li><input type="checkbox" /> Buy milk <button>×</button></li>
      </ul>
    </div>
  );
}

L2 Add a todo

Controlled input, submit on the form, clear the box.

const [todos, setTodos] = useState([]);
const [text, setText] = useState("");

function add(e) {
  e.preventDefault();                    // stop page reload
  const t = text.trim();
  if (!t) return;                        // ignore empty
  setTodos([...todos, { id: crypto.randomUUID(), text: t, done: false }]);
  setText("");                           // clear the input
}

<form onSubmit={add}>
  <input value={text} onChange={e => setText(e.target.value)} />
  <button>Add</button>
</form>

A <form> gives you Enter-to-submit for free. A bare onClick button does not.

L3 Toggle and delete — without mutating

map to change one, filter to drop one. Both return new arrays.

const toggle = id =>
  setTodos(ts => ts.map(t =>
    t.id === id ? { ...t, done: !t.done } : t   // new object for the one
  ));

const remove = id =>
  setTodos(ts => ts.filter(t => t.id !== id));

// t.done = !t.done  → mutation, React sees the same array, no re-render

L4 Filter — derived, never stored

One string of state, computed on the way to render.

const [filter, setFilter] = useState("all");

const shown = todos.filter(t =>
  filter === "active" ? !t.done :
  filter === "done"   ?  t.done : true
);
const left = todos.filter(t => !t.done).length;   // → 2

{["all","active","done"].map(f => (
  <button key={f} onClick={() => setFilter(f)}
    aria-pressed={filter === f}>{f}</button>
))}

The whole thing

import { useState } from "react";

export default function TodoList() {
  const [todos, setTodos] = useState([]);
  const [text, setText] = useState("");
  const [filter, setFilter] = useState("all");

  function add(e) {
    e.preventDefault();
    const t = text.trim();
    if (!t) return;
    setTodos(ts => [...ts, { id: crypto.randomUUID(), text: t, done: false }]);
    setText("");
  }
  const toggle = id => setTodos(ts =>
    ts.map(t => (t.id === id ? { ...t, done: !t.done } : t)));
  const remove = id => setTodos(ts => ts.filter(t => t.id !== id));

  const shown = todos.filter(t =>
    filter === "active" ? !t.done : filter === "done" ? t.done : true);
  const left = todos.filter(t => !t.done).length;

  return (
    <div>
      <form onSubmit={add}>
        <input value={text} onChange={e => setText(e.target.value)}
               placeholder="Add a todo" aria-label="New todo" />
        <button>Add</button>
      </form>

      {["all", "active", "done"].map(f => (
        <button key={f} onClick={() => setFilter(f)}
                aria-pressed={filter === f}>{f}</button>
      ))}

      <ul>
        {shown.map(t => (
          <li key={t.id}>
            <input type="checkbox" checked={t.done}
                   onChange={() => toggle(t.id)} />
            <span style={{ textDecoration: t.done ? "line-through" : "none" }}>
              {t.text}
            </span>
            <button onClick={() => remove(t.id)}
                    aria-label={`Delete ${t.text}`}>×</button>
          </li>
        ))}
      </ul>

      <p>{left} left</p>
      {shown.length === 0 && <p>Nothing here.</p>}
    </div>
  );
}

Gotchas

Mutating the array or the todo todos.push(...) or t.done = true keeps the same reference, so React skips the re-render. Always build a new array: [...todos, x], map, filter.
key={index} Delete the first item and every key shifts — React reuses the wrong DOM node, and checkbox / input state lands on the wrong row. Use a real id.
Storing the filtered list in state Two sources of truth that drift apart. Derive shown during render instead.
Forgetting e.preventDefault() The form submits, the page reloads, your state is gone. Looks like “add doesn't work”.
checked without onChange React warns and the checkbox freezes. Pair them, or use defaultChecked.

If they push

“Add editing on double-click.” Add editingId to state. When t.id === editingId, render an input instead of the span; save on blur or Enter with the same map pattern.
“Persist across reloads.” useEffect(() => localStorage.setItem("todos", JSON.stringify(todos)), [todos]), and lazy-init: useState(() => JSON.parse(localStorage.getItem("todos") ?? "[]")).
“Now make it 1000 items.” Split each row into a memoized <Todo>, pass stable callbacks via useCallback, and move to setTodos(ts => ...) everywhere. Beyond ~5k rows, virtualize.
“Too many handlers — tidy the state.” Move to useReducer with {type:"add"|"toggle"|"remove"}. All list transitions live in one function.
“Keyboard and screen readers?” The form handles Enter. Delete buttons need aria-label. Filters get aria-pressed. Wrap each checkbox in a <label> so the text is clickable.

Say this out loud

  • “One array is my source of truth — the filtered list is derived, not stored.”
  • “I'll give each todo a real id, because index keys break the moment you delete.”
  • “Every update returns a new array — map to change one, filter to drop one.”
  • “I'm using a form so Enter submits, and I trim the text to reject empty todos.”
  • “Delete buttons get an aria-label; the filter buttons get aria-pressed.”
  • “Styling is deliberately thin — tell me if you'd rather I spend time there.”
