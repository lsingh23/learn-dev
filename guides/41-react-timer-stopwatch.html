41. Timer & Stopwatch

Start, pause, reset, mm:ss. A 10-minute warm-up that quietly tests effects, cleanup and stale closures.

The ask

Interviewer "Build a stopwatch. Start, pause, reset, and show the time as mm:ss. Then tell me why it drifts."

A number that goes up on its own while a flag says it should.

What we're building

Stopwatch — running state
● running derived from state
02:07.4
▲ one number in state: elapsed ms
Pause Lap Reset
▲ label flips Start ⇄ Pause
Lap 300:41.2
Lap 200:52.9
Lap 100:33.3
▲ optional — only if they ask

It should:

  • Start counting on Start.
  • Freeze on Pause, keep the value.
  • Resume from where it stopped.
  • Reset to 00:00.
  • Show mm:ss, zero-padded.
  • Stop the interval when unmounted.

Styling barely matters here. The clock ticking correctly is the whole score.

The mental model

One boolean drives one interval. isRunning flips → the effect tears the old interval down and builds a new one. You never start or stop a timer inside a click handler.

The shape of the state

const [elapsed, setElapsed]     = useState(0);     // ms since start — the ONLY truth
const [isRunning, setIsRunning] = useState(false); // should the interval exist?

That's it. mm:ss is derived every render — never stored.

Rule of thumb Store the rawest value you have (a number of ms). Anything you could compute from it — the label, the padding, "is it over a minute" — is a variable, not state.

Build it in layers

In an interview, build L1 and L2 out loud, get it ticking, then ask "want me to add lap times or make it drift-free?"

L1 Static markup

Dumbest thing that renders.

function Stopwatch(){
  return (
    <div>
      <h1>00:00</h1>
      <button>Start</button>
      <button>Reset</button>
    </div>
  );
}

L2 It ticks

One effect, keyed on isRunning, with cleanup.

const [elapsed, setElapsed] = useState(0);
const [isRunning, setIsRunning] = useState(false);

useEffect(() => {
  if (!isRunning) return;
  const id = setInterval(() => setElapsed(e => e + 100), 100);
  return () => clearInterval(id);   // ← never optional
}, [isRunning]);

L3 Format it

A pure function outside the component.

function format(ms){
  const total = Math.floor(ms / 1000);
  const mm = String(Math.floor(total / 60)).padStart(2, "0");
  const ss = String(total % 60).padStart(2, "0");
  return `${mm}:${ss}`;
}
format(127400) // → "02:07"

L4 Controls

Buttons only flip state. They never touch the timer.

<button onClick={() => setIsRunning(r => !r)}>
  {isRunning ? "Pause" : "Start"}
</button>
<button onClick={() => { setIsRunning(false); setElapsed(0); }}>
  Reset
</button>

The whole thing

import { useState, useEffect } from "react";

function format(ms){
  const total = Math.floor(ms / 1000);
  const mm = String(Math.floor(total / 60)).padStart(2, "0");
  const ss = String(total % 60).padStart(2, "0");
  return `${mm}:${ss}`;
}

export default function Stopwatch(){
  const [elapsed, setElapsed] = useState(0);
  const [isRunning, setIsRunning] = useState(false);

  useEffect(() => {
    if (!isRunning) return;
    const id = setInterval(() => setElapsed(e => e + 100), 100);
    return () => clearInterval(id);
  }, [isRunning]);

  return (
    <div>
      <h1 aria-live="polite">{format(elapsed)}</h1>
      <button onClick={() => setIsRunning(r => !r)}>
        {isRunning ? "Pause" : "Start"}
      </button>
      <button
        onClick={() => { setIsRunning(false); setElapsed(0); }}
        disabled={elapsed === 0}
      >
        Reset
      </button>
    </div>
  );
}

Gotchas

No clearInterval in the cleanup. Every start stacks another interval. Two intervals = the clock runs at double speed, and it keeps running after unmount. Return () => clearInterval(id), always.
Stale closure: setElapsed(elapsed + 100). The callback captured elapsed from the render that created it — forever 0 + 100. The clock freezes at 00:00. Use the functional updater setElapsed(e => e + 100), which reads the latest value.
Same interval, two updaters
setElapsed(elapsed + 100)
tick 1 → 100
tick 2 → 100
tick 3 → 100
setElapsed(e => e + 100)
tick 1 → 100
tick 2 → 200
tick 3 → 300
Storing the formatted string in state. useState("00:00") means you can't add milliseconds, laps or a countdown later. Store ms; derive the string.
Assuming setInterval(fn, 1000) fires every 1000 ms. It fires at least 1000 ms later, and background tabs throttle it to ~1/sec or less. Counting ticks drifts seconds per minute. See below for the fix.
Reset leaves it running. Reset must set both: setIsRunning(false) and setElapsed(0).

If they push

"Make it accurate — no drift." Stop counting ticks. Remember when you started and subtract. The interval becomes a repaint trigger, not the clock. 
const startRef = useRef(0);   // a ref — a box that survives re-renders
const baseRef  = useRef(0);   // ms banked from previous runs

useEffect(() => {
  if (!isRunning) return;
  startRef.current = Date.now();
  const id = setInterval(() => {
    setElapsed(baseRef.current + (Date.now() - startRef.current));
  }, 50);
  return () => {
    clearInterval(id);
    baseRef.current += Date.now() - startRef.current;  // bank it on pause
  };
}, [isRunning]);

Late ticks no longer lose time — the next one reads the real clock. Reset must also zero baseRef.current.

"Now make it a countdown." Same machinery, flipped. Keep a duration, render duration - elapsed, and stop at zero: 
const left = Math.max(0, duration - elapsed);
useEffect(() => { if (left === 0) setIsRunning(false); }, [left]);
Clamp with Math.max(0, …) so a late tick can't show -00:01.
"Add lap times." Store the absolute marks, derive the splits. 
const [laps, setLaps] = useState([]);          // [1200, 4500, 7100]
const lap = () => setLaps(l => [...l, elapsed]);
const splits = laps.map((t, i) => t - (laps[i - 1] ?? 0));
"Show milliseconds." Tick at ~16 ms (or use requestAnimationFrame) and extend format: String(ms % 1000).padStart(3,"0"). Nothing else changes — that's the payoff for storing ms.
"What if the tab is backgrounded?" Timers throttle, but the Date.now() version is immune: it recomputes from real time the moment the tab wakes.
"Extract a useStopwatch hook." Move both states plus the effect into a hook, return { elapsed, isRunning, start, pause, reset }. The component becomes markup only.

Say this out loud

  • "I'll keep elapsed milliseconds in state and derive mm:ss on render — one source of truth."
  • "The effect depends on isRunning, so flipping it tears down the old interval and starts a new one."
  • "I always return clearInterval — otherwise intervals stack and the clock runs double speed."
  • "Functional updater here, because the interval callback would otherwise close over a stale value."
  • "setInterval drifts, so if you want accuracy I'd store a start timestamp and diff against Date.now()."
  • "I'll put aria-live polite on the time and disable Reset at zero — styling I'll leave rough unless you want it."
