51. OTP Input

Six boxes, one code. Tests whether you can move focus around the DOM on purpose.

The ask

Interviewer "Build a 6-digit OTP input. Typing a digit jumps to the next box, backspace goes back, and pasting a code from SMS should fill every box at once."

Six inputs that behave like one field.

Verify
Type 9 → box 3 shows 9, focus jumps to box 4. Backspace in an empty box 3 → focus jumps back to box 2.

It should:

  • Hold exactly one character per box
  • Move focus forward when you type
  • Move focus back on backspace in an empty box
  • Fill all six boxes from one paste
  • Ignore letters and symbols
  • Fire onComplete when all six are filled

Styling barely matters here. Focus movement is what's scored.

The mental model

Two parallel arrays. One of values that React owns and re-renders. One of DOM nodes so you can call .focus() on a neighbour. Typing writes to the first, then pokes the second.

What's a ref? A ref is a direct handle on the DOM node — so you can call browser methods like .focus() that React has no prop for.

The shape of the state

// one source of truth: the six characters
const [digits, setDigits] = useState(Array(6).fill(''));

// NOT state — a plain box of the 6 DOM nodes, for .focus()
const inputs = useRef([]);

// derived, never stored:
const code = digits.join('');        // → "481"
const filled = code.length === 6;    // → false
Rule of thumb Anything you can compute from digits is not state. Focus lives in the DOM, not in React — so it lives in a ref.

Build it in layers

In an interview, build L1 and L2 out loud first, then ask "want me to add paste and backspace?"

L1 Six dumb boxes

No state. Just prove the layout renders.

<div style={{ display: 'flex', gap: 8 }}>
  {Array.from({ length: 6 }).map((_, i) => (
    <input key={i} maxLength={1} style={{ width: 40, textAlign: 'center' }} />
  ))}
</div>

L2 Controlled + digits only

State owns the values. Take only the last character typed, and only if it's a digit.

const handleChange = (i, raw) => {
  const ch = raw.slice(-1);                 // "48" → "8", never two in a box
  if (ch && !/^[0-9]$/.test(ch)) return;    // reject letters/symbols
  const next = [...digits];
  next[i] = ch;
  setDigits(next);
};

<input value={digits[i]} onChange={e => handleChange(i, e.target.value)} />

L3 Focus: auto-advance and backspace

Collect the nodes into a ref array, then move focus by index.

const inputs = useRef([]);
<input ref={el => { inputs.current[i] = el; }} ... />

const focus = i => inputs.current[i]?.focus();

// in handleChange, after setDigits:
if (ch && i < 5) focus(i + 1);

const handleKeyDown = (i, e) => {
  if (e.key === 'Backspace' && !digits[i] && i > 0) focus(i - 1);
};
Backspace, precisely Box has a value → the browser clears it, focus stays. Box already empty → we jump back. Two presses to leave a filled box. That's what users expect.

L4 Paste + onComplete

One paste fills every box; focus lands on the last one filled.

const handlePaste = e => {
  e.preventDefault();                                    // don't dump 6 chars in one box
  const chars = e.clipboardData.getData('text').replace(/\D/g, '').slice(0, 6).split('');
  if (!chars.length) return;
  const next = Array(6).fill('');
  chars.forEach((c, i) => { next[i] = c; });
  setDigits(next);
  focus(Math.min(chars.length, 5));
};

useEffect(() => {
  const code = digits.join('');
  if (code.length === 6) onComplete?.(code);            // fires once, when full
}, [digits]);

The whole thing

import { useState, useRef, useEffect } from 'react';

export default function OtpInput({ length = 6, onComplete }) {
  const [digits, setDigits] = useState(Array(length).fill(''));
  const inputs = useRef([]);
  const focus = i => inputs.current[i]?.focus();

  useEffect(() => {
    const code = digits.join('');
    if (code.length === length) onComplete?.(code);
  }, [digits]);

  const write = (next, moveTo) => { setDigits(next); if (moveTo != null) focus(moveTo); };

  const handleChange = (i, raw) => {
    const ch = raw.slice(-1);
    if (ch && !/^[0-9]$/.test(ch)) return;
    const next = [...digits];
    next[i] = ch;
    write(next, ch && i < length - 1 ? i + 1 : null);
  };

  const handleKeyDown = (i, e) => {
    if (e.key === 'Backspace' && !digits[i] && i > 0) focus(i - 1);
    if (e.key === 'ArrowLeft' && i > 0) focus(i - 1);
    if (e.key === 'ArrowRight' && i < length - 1) focus(i + 1);
  };

  const handlePaste = e => {
    e.preventDefault();
    const chars = e.clipboardData.getData('text').replace(/\D/g, '').slice(0, length).split('');
    if (!chars.length) return;
    const next = Array(length).fill('');
    chars.forEach((c, i) => { next[i] = c; });
    write(next, Math.min(chars.length, length - 1));
  };

  return (
    <div style={{ display: 'flex', gap: 8 }} onPaste={handlePaste}>
      {digits.map((d, i) => (
        <input
          key={i}
          ref={el => { inputs.current[i] = el; }}
          value={d}
          onChange={e => handleChange(i, e.target.value)}
          onKeyDown={e => handleKeyDown(i, e)}
          onFocus={e => e.target.select()}
          inputMode="numeric"
          autoComplete="one-time-code"
          aria-label={`Digit ${i + 1} of ${length}`}
          maxLength={1}
          style={{ width: 44, height: 52, textAlign: 'center', fontSize: 22 }}
        />
      ))}
    </div>
  );
}

Gotchas

Using e.target.value raw. A box with "4" plus a typed "8" gives "48". Take .slice(-1) so a box never holds two.
Six pieces of state, or six uncontrolled inputs. One array. Reading the code back out of the DOM at submit time is the thing that loses points.
Advancing on backspace. Only move back when the box is already empty — otherwise one press eats two digits.
Forgetting e.preventDefault() on paste. Without it the browser also drops all six characters into the focused box.
ref as an array you rebuild each render. useRef([]) once, assign by index in the callback. Don't useState for nodes — it re-renders forever.

If they push

"Arrow keys?" Already in handleKeyDown: ArrowLeft/ArrowRight move focus one box, no value change.
"Clicking a filled box should replace, not append." onFocus={e => e.target.select()} — selects the character so the next keypress overwrites it.
"Make it work on phones." inputMode="numeric" for the number pad, autoComplete="one-time-code" so iOS/Android offer the SMS code — the paste handler then fills all six.
"Mask the digits." Keep digits as the truth, render a mask: 
<input value={d ? (masked ? '•' : d) : ''} ... />
Don't use type="password" — it breaks the numeric keypad.
"Variable length? Alphanumeric?" length is already a prop. Swap the regex to /^[0-9a-zA-Z]$/ and drop replace(/\D/g,'') in paste.

Say this out loud

  • "State is one array of six characters — everything else I derive from it."
  • "Focus isn't state, it's a DOM thing, so I'll keep a ref array of the six inputs."
  • "I only take the last character typed, so a box can never hold two."
  • "Backspace only jumps back when the box is already empty — otherwise you'd lose two digits."
  • "Paste is its own handler: preventDefault, strip non-digits, spread across the boxes."
  • "Each box gets an aria-label, plus inputMode numeric and one-time-code for mobile."
