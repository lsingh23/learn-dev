52. Toast Notifications

A queue of little messages in a corner. Tests arrays-by-id, timers, and Context.

The ask

Interviewer "Build a toast system. Any component in the app can fire a notification; they stack in the corner, disappear after 3 seconds, and can be closed by hand."

Plain English: an array of messages, each with an id, that removes itself on a timer.

It should:

  • Stack multiple toasts, newest last
  • Auto-dismiss each after ~3 seconds
  • Close on ✕ click, immediately
  • Support success / error / info types
  • Be callable from any component, no props
  • Render above everything (portal)
  • Announce itself to screen readers

The mental model

One array lives at the top. Anyone can push to it. Each toast removes itself by id.

The one idea Everything is keyed by id, never by position. Positions shift; ids don't.

The shape of the state

const [toasts, setToasts] = useState([]);
// [
//   { id: 1,               // unique, permanent handle — the whole system hinges on this
//     type: 'success',     // drives colour + icon; data, not branches in JSX
//     message: 'Saved' }   // what the user reads
// ]

const nextId = useRef(0); // a ref = a box that survives re-renders

Rule of thumb: one array is the source of truth. Order is render order. Timers are not state — they live inside each toast.

Build it in layers

In an interview: build L1 and L2 out loud, then ask "want me to add Context and auto-dismiss?"

L1 Dumbest thing that renders

Hard-coded array. No state, no timers.

const toasts = [{ id: 1, type: 'success', message: 'Saved' }];

<div className="toast-stack">
  {toasts.map(t => (
    <div key={t.id} className={`toast ${t.type}`}>
      {t.message} <button>✕</button>
    </div>
  ))}
</div>

L2 Add + remove by id

Push with a fresh id; filter that id out.

const [toasts, setToasts] = useState([]);
const nextId = useRef(0);

const addToast = (message, type = 'info') =>
  setToasts(ts => [...ts, { id: nextId.current++, type, message }]);

const removeToast = (id) =>
  setToasts(ts => ts.filter(t => t.id !== id));   // ← by id, never by index

L3 Each toast owns its timer

The child sets its own setTimeout and cleans it up. The parent juggles nothing.

function Toast({ toast, onClose }) {
  useEffect(() => {
    const t = setTimeout(() => onClose(toast.id), 3000);
    return () => clearTimeout(t);          // cleanup on unmount
  }, [toast.id, onClose]);                 // onClose must be stable — useCallback

  return (
    <div className={`toast ${toast.type}`} role="status">
      <span>{ICONS[toast.type]}</span>
      {toast.message}
      <button onClick={() => onClose(toast.id)} aria-label="Dismiss">✕</button>
    </div>
  );
}

L4 Context + useToast() + portal

This is the point of the question: fire a toast from anywhere, zero prop drilling.

The whole thing

const ToastCtx = createContext(null);
export const useToast = () => useContext(ToastCtx);
const ICONS = { success: '✓', error: '✕', info: 'i' };

function Toast({ toast, onClose }) {
  useEffect(() => {
    const t = setTimeout(() => onClose(toast.id), 3000);
    return () => clearTimeout(t);
  }, [toast.id, onClose]);

  return (
    <div className={`toast ${toast.type}`}>
      <span>{ICONS[toast.type]}</span>
      <span>{toast.message}</span>
      <button onClick={() => onClose(toast.id)} aria-label="Dismiss">✕</button>
    </div>
  );
}

export function ToastProvider({ children }) {
  const [toasts, setToasts] = useState([]);
  const nextId = useRef(0);

  const removeToast = useCallback((id) =>
    setToasts(ts => ts.filter(t => t.id !== id)), []);

  const api = useMemo(() => {
    const add = (message, type) =>
      setToasts(ts => [...ts, { id: nextId.current++, type, message }]);
    return {
      success: (m) => add(m, 'success'),
      error:   (m) => add(m, 'error'),
      info:    (m) => add(m, 'info'),
    };
  }, []);

  return (
    <ToastCtx.Provider value={api}>
      {children}
      {createPortal(
        <div className="toast-stack" aria-live="polite" aria-atomic="false">
          {toasts.map(t => (
            <Toast key={t.id} toast={t} onClose={removeToast} />
          ))}
        </div>,
        document.body
      )}
    </ToastCtx.Provider>
  );
}

CSS: .toast-stack{position:fixed;top:1rem;right:1rem;display:flex;flex-direction:column;gap:.5rem}

Gotchas

Dismissing by index. splice(i,1) inside a timer captures a stale index — toast 2's timer fires after toast 1 already left, and kills the wrong one. Filter by id.
Stale state in the timer. setToasts(toasts.filter(...)) closes over an old array. Always use the updater form: setToasts(ts => ...).
Unstable onClose. A new function every render re-runs the effect, restarting the 3s timer forever — the toast never dies. Wrap it in useCallback.
Using array index as key. Remove the first toast and React reuses the wrong DOM node — text swaps, animation jumps. key={t.id}.
The parent holding a map of timers. Works, but you now hand-clear on unmount, on manual close, on re-render. Let the child own it.

If they push

"Pause the timer on hover." Store the deadline in a ref; clear on mouseenter, restart with the remaining time on mouseleave. 
const left = useRef(3000), start = useRef(0);
const pause = () => { clearTimeout(id.current);
  left.current -= Date.now() - start.current; };
const resume = () => { start.current = Date.now();
  id.current = setTimeout(() => onClose(toast.id), left.current); };
"Only show 3 at a time, queue the rest." Keep the full array; render toasts.slice(0, 3). Unrendered toasts have no timer, so they wait automatically and start counting when they scroll into the visible slice.
"Animate them out." Removal unmounts instantly, so there's nothing to animate. Add exiting: true to the toast, wait for onAnimationEnd, then filter it out. Or use a library (Framer Motion AnimatePresence).
"Screen readers?" Wrap the stack in aria-live="polite" so new toasts are announced without stealing focus. Errors can use role="alert" (assertive). Give ✕ an aria-label. Never auto-dismiss something the user must act on.
"Same message fired 10 times?" Dedupe on add: if a toast with the same message exists, bump its id/timer instead of pushing a new one — or show a count badge.

Say this out loud

  • "State is one array of toasts — id, type, message. The id is the handle for everything."
  • "I'll remove by id, not index, so a firing timer can't delete the wrong toast."
  • "Each Toast owns its own setTimeout in an effect with cleanup — the parent doesn't track N timers."
  • "onClose goes through useCallback, otherwise the effect restarts and it never dismisses."
  • "Context plus a useToast hook, so any component fires one without prop drilling."
  • "Stack is portalled to body with aria-live polite, so it isn't clipped and is announced."
  • "Styling I'd keep minimal — happy to add hover-pause or a max-visible queue if you want."
