50. Nested Checkboxes

A checkbox tree. Parents drive children down; children decide parents up.

The ask

Interviewer "Render this category tree with checkboxes. Checking a parent checks everything under it. If only some children are checked, the parent shows a dash."

Two flows through one tree: selection falls down, status bubbles up.

What we're building

Category picker

It should:

  • Check a parent → check every descendant.
  • Uncheck a parent → uncheck every descendant.
  • All children on → parent on.
  • Some children on → parent dashed.
  • No children on → parent off.
  • Work at any depth, any branching.

The mental model

Only the leaves hold state. Every parent's box is computed from the leaves below it — never stored. One source of truth, so the two directions can never disagree.

Unchecked

0 of 2 → false

Indeterminate

1 of 2 → indeterminate

Checked

2 of 2 → true

The shape of the state

// the tree — static data, not state
const TREE = { id:'all', label:'All', children:[
  { id:'fruit', label:'Fruit', children:[
      {id:'apple',label:'Apple'}, {id:'mango',label:'Mango'} ]},
  { id:'veg', label:'Vegetables', children:[
      {id:'carrot',label:'Carrot'}, {id:'peas',label:'Peas'} ]},
]};

// ALL the state: which leaves are on. Nothing else.
const [checked, setChecked] = useState(() => new Set());
// → Set { 'apple', 'mango', 'carrot' }
Rule of thumb If a value can be computed from other state, don't store it. A stored parent flag is a second truth you must remember to sync — and you will forget.

Build it in layers

In an interview, build L1 and L2 first, out loud, then ask "want me to add the parent roll-up?" Styling barely matters here; the recursion and the third state are what's scored.

L1 Render the tree, no state

Dumbest thing that draws. A component that calls itself.

function Node({ node }) {
  return (
    <li>
      <label><input type="checkbox" /> {node.label}</label>
      {node.children && (
        <ul>{node.children.map(c => <Node key={c.id} node={c} />)}</ul>
      )}
    </li>
  );
}

L2 Leaves toggle themselves

One Set of ids at the top; every checkbox reads and writes it.

const on = checked.has(node.id);

<input type="checkbox" checked={on}
  onChange={() => setChecked(prev => {
    const next = new Set(prev);        // copy — never mutate state
    on ? next.delete(node.id) : next.add(node.id);
    return next;
  })} />

L3 DOWN — a parent writes all its leaves

Flatten the node to its leaf ids, then add or remove them all at once.

const leafIds = n => n.children ? n.children.flatMap(leafIds) : [n.id];
// leafIds(TREE) → ['apple','mango','carrot','peas']

function toggle(node, turnOn) {
  setChecked(prev => {
    const next = new Set(prev);
    leafIds(node).forEach(id => turnOn ? next.add(id) : next.delete(id));
    return next;
  });
}

L4 UP — derive the parent, incl. the dash

One recursive read. Then the trick: indeterminate is a DOM property, not an HTML attribute — JSX can't set it, so you reach the element with a ref (a callback that hands you the real DOM node).

function stateOf(node, checked) {              // 'on' | 'off' | 'mixed'
  if (!node.children) return checked.has(node.id) ? 'on' : 'off';
  const kids = node.children.map(c => stateOf(c, checked));
  if (kids.every(s => s === 'on'))  return 'on';
  if (kids.every(s => s === 'off')) return 'off';
  return 'mixed';
}

const s = stateOf(node, checked);
<input type="checkbox"
  checked={s === 'on'}
  ref={el => el && (el.indeterminate = s === 'mixed')}
  onChange={() => toggle(node, s !== 'on')} />   // mixed → click turns all ON

The whole thing

import { useState } from 'react';

const leafIds = n => (n.children ? n.children.flatMap(leafIds) : [n.id]);

function stateOf(node, checked) {
  if (!node.children) return checked.has(node.id) ? 'on' : 'off';
  const kids = node.children.map(c => stateOf(c, checked));
  if (kids.every(s => s === 'on'))  return 'on';
  if (kids.every(s => s === 'off')) return 'off';
  return 'mixed';
}

function Node({ node, checked, onToggle }) {
  const s = stateOf(node, checked);
  return (
    <li>
      <label>
        <input
          type="checkbox"
          checked={s === 'on'}
          ref={el => el && (el.indeterminate = s === 'mixed')}
          onChange={() => onToggle(node, s !== 'on')}
        />{' '}
        {node.label}
      </label>
      {node.children && (
        <ul>
          {node.children.map(c => (
            <Node key={c.id} node={c} checked={checked} onToggle={onToggle} />
          ))}
        </ul>
      )}
    </li>
  );
}

export default function CheckTree({ tree }) {
  const [checked, setChecked] = useState(() => new Set());

  const onToggle = (node, turnOn) =>
    setChecked(prev => {
      const next = new Set(prev);
      leafIds(node).forEach(id => (turnOn ? next.add(id) : next.delete(id)));
      return next;
    });

  return <ul><Node node={tree} checked={checked} onToggle={onToggle} /></ul>;
}

Gotchas

Writing indeterminate in JSX. <input indeterminate /> does nothing — React drops unknown attributes. It's a property on the DOM node; set it through a ref.
Storing a checked flag on parents too. Two truths that drift. Derive parents from leaves instead.
Mutating the Set or the tree in place. prev.add(id); return prev; is the same object — React skips the re-render. Copy first.
Forgetting a parent with zero children. [].every(...) is true, so an empty folder reads as "on". Guard it if your data allows it.
No key on the recursive map. Free points lost, and checkbox DOM state gets reused across the wrong rows.

If they push

"Why a flat Set instead of flags in the tree?" The Set is O(1) to read/write and the tree stays immutable data you never clone. Flags in the tree mean a recursive copy on every click, plus syncing parents by hand.
"Now do it with the flags in the tree." Rebuild only the path you touched: 
const setAll = (n, v) => ({ ...n, checked: v,
  children: n.children?.map(c => setAll(c, v)) });
"10,000 nodes?" stateOf re-walks the tree per node — O(n²). Compute every node's state in one bottom-up pass into a Map, pass it down, and virtualise the rows so only what's on screen renders.
"Add Select all." Already there — that's onToggle(root, true). The root's own checkbox is the select-all, dash included.
"Keyboard and screen readers?" Real <input>s in <label>s give you Tab and Space for free. Add role="tree" / role="treeitem" with aria-checked="mixed", and arrow keys to move between rows.

Say this out loud

  • "The only state I'll keep is a Set of checked leaf ids — everything above is derived."
  • "Clicking a node writes down to its leaves; rendering reads back up. One write path, one read path."
  • "The parent has three states, so I need indeterminate — that's a DOM property, so I'll set it via a ref."
  • "I'm copying the Set before mutating, otherwise React won't see a change."
  • "A partially-checked parent should turn everything on when clicked — that's the convention users expect."
  • "If the tree got huge I'd precompute states in one pass and virtualise the list."
