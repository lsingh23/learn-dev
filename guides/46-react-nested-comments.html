It should:

  • Render children at any depth.
  • Stop when a node has no children.
  • Toggle a node open / closed.
  • Indent by depth, not by nesting hacks.
  • Add a reply deep in the tree.
  • Keep the tree immutable on update.

The mental model

One component, <Node>. It renders itself, then maps over its children and renders <Node> again. The base case — no children — is what stops it.

The shape of the state

// ONE tree in the parent. Nothing else.
const tree = {
  id: 1,                // stable key + the address we update by
  text: 'recursion…',   // or name: 'src' for a file tree
  children: [           // [] = leaf. undefined = file. Same base case.
    { id: 2, text: '…', children: [
      { id: 4, text: '…', children: [] }
    ]},
    { id: 3, text: '…', children: [] }
  ]
};

Per-node UI state — open/closed, reply box showing, draft text — lives inside <Node> as plain useState.

Rule of thumb Data that outlives the node goes in the parent tree. Data that dies with the node (is it open? what am I typing?) stays local — otherwise the parent needs a map of every id in the tree, and you have to clean it up.

Build it in layers

In an interview: build L1 and L2 out loud, get it rendering, then ask "want me to add replies?"

L1 Dumbest thing that renders

Hard-coded, no state, no recursion. Prove the markup.

function Node({ node }) {
  return <div className="node">{node.text}</div>;
}
<Node node={{ id: 1, text: 'hello', children: [] }} />

L2 Recurse + indent

Render children with the same component. depth drives padding.

function Node({ node, depth = 0 }) {
  return (
    <div>
      <div className="node" style={{ paddingLeft: depth * 16 }}>
        {node.text}
      </div>
      {node.children.map(c =>                // [] → renders nothing
        <Node key={c.id} node={c} depth={depth + 1} />   // ← base case is the empty array
      )}
    </div>
  );
}

L4 Add a reply — the immutable recursive update

This is the part they're testing. You can't mutate; you rebuild the path down to the target and reuse every untouched branch.

// returns a NEW tree with `child` appended under `targetId`
function addChild(node, targetId, child) {
  if (node.id === targetId) {                     // found it
    return { ...node, children: [...node.children, child] };
  }
  return {
    ...node,
    children: node.children.map(c =>              // recurse into each branch
      addChild(c, targetId, child)
    )
  };
}

// in the parent:
setTree(t => addChild(t, id, { id: crypto.randomUUID(), text, children: [] }));
Why it works Every node on the path to the target gets a new object, so React sees the change. Branches you didn't touch are the same objects — cheap, and memo-friendly. Deleting is the same function with .filter(c => c.id !== targetId).

The whole thing

function addChild(node, targetId, child) {
  if (node.id === targetId) return { ...node, children: [...node.children, child] };
  return { ...node, children: node.children.map(c => addChild(c, targetId, child)) };
}

function Node({ node, depth = 0, onReply }) {
  const [open, setOpen] = useState(true);      // local: dies with the node
  const [draft, setDraft] = useState(null);    // null = reply box hidden
  const hasKids = node.children.length > 0;

  const submit = () => { if (draft.trim()) onReply(node.id, draft); setDraft(null); };

  return (
    <div>
      <div className="node" style={{ paddingLeft: depth * 16 }}>
        <button onClick={() => setOpen(o => !o)} aria-expanded={open}
                style={{ visibility: hasKids ? 'visible' : 'hidden' }}>
          {open ? '▾' : '▸'}
        </button>
        {node.text}
        <button onClick={() => setDraft('')}>Reply</button>
      </div>

      {draft !== null && (
        <div style={{ paddingLeft: (depth + 1) * 16 }}>
          <input value={draft} onChange={e => setDraft(e.target.value)} autoFocus />
          <button onClick={submit}>Post</button>
          <button onClick={() => setDraft(null)}>Cancel</button>
        </div>
      )}

      {open && node.children.map(c =>                      // base case: [] renders nothing
        <Node key={c.id} node={c} depth={depth + 1} onReply={onReply} />
      )}
    </div>
  );
}

export default function Thread({ initial }) {
  const [tree, setTree] = useState(initial);
  const reply = (id, text) =>
    setTree(t => addChild(t, id, { id: crypto.randomUUID(), text, children: [] }));
  return <Node node={tree} onReply={reply} />;
}

Styling barely matters here. Logic and the recursive update are what's scored.

Gotchas

Mutating the tree. node.children.push(reply) changes the object React already has — same reference, no re-render. Always rebuild the path.
No base case. If children can be undefined, node.children.map throws. Guard once: const kids = node.children ?? [].
Index as key. Insert a reply at the top and every sibling's local open/draft state shifts to the wrong node. Key by id.
Indenting with nested markup. Wrapping each level in a padded <div> works until you want zebra rows, hover, or full-width selection — the row no longer spans the container. Keep rows flat siblings and push the content over with paddingLeft: depth * 16.
Lifting open/closed to the parent. Now the parent owns { [id]: bool } for every node forever. Only do it if the feature demands it (see collapse-all).

If they push

"The API gives a flat list with parentId." Build the tree once with a Map of id → node, then link children in a second pass. O(n). 
function build(rows) {
  const byId = new Map(rows.map(r => [r.id, { ...r, children: [] }]));
  let root = null;
  for (const r of rows) {
    const n = byId.get(r.id);
    r.parentId ? byId.get(r.parentId).children.push(n) : root = n;
  }
  return root;   // wrap in useMemo(() => build(rows), [rows])
}
"Add collapse-all." Local state can't be reached from outside — so lift only this one: keep openIds (a Set) in the parent, pass it down. Collapse-all = setOpenIds(new Set()).
"10,000 nodes." Closed folders already cost nothing. Then: React.memo(Node) (untouched branches keep their identity, so they skip), and virtualize by flattening the visible nodes into one array and rendering that with a windowing list.
"Trees so deep they blow the stack." Rare in UI (you'd never render 10k deep), but rewrite addChild iteratively with an explicit stack, or cap displayed depth like Reddit does with a "continue this thread" link.
"Make it accessible." role="tree" on the container, role="treeitem" + aria-expanded on each row, arrow keys to move, right/left to open/close.

Say this out loud

  • "A comment thread and a file tree are the same problem — one component that renders itself."
  • "The base case is a node with no children; the map over an empty array just renders nothing."
  • "I'll keep open/closed and the reply draft local to each node, so the parent doesn't hold a map of every id."
  • "Adding a reply has to be immutable — I'll recurse and rebuild only the path to the target."
  • "Indentation is paddingLeft: depth * 16, so every row is still a full-width flat sibling."
  • "If this got huge I'd memo the node and flatten the visible rows for virtualization."
