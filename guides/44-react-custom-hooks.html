44. Custom Hooks: useDebounce & useLocalStorage

Two hooks that show you can package stateful logic — and clean up after it.

The ask

Interviewer "Write two custom hooks: useDebounce(value, delay) that returns the value after it stops changing, and useLocalStorage(key, initial) that behaves like useState but persists."

Plain English: move the timer logic and the storage logic out of the component, into reusable functions.

What a custom hook actually is A plain function whose name starts with use and that calls other hooks inside. No magic, no registration, no React API. That's it.

Rules of hooks, one line: call hooks at the top level of a component or another hook — never inside if, loops, or callbacks.

It should:

  • Debounced value updates only after the pause
  • Typing again restarts the timer
  • Unmounting cancels the pending timer
  • Stored value read once, on first render
  • Setter writes to state and storage
  • Support setValue(v => !v)
  • Never crash on bad JSON or no window

The mental model

A custom hook is just your component's code, moved. It still owns real state, and each component that calls it gets its own separate copy.

Both hooks are the same two-part shape:

HookState it holdsSide effect it runs
useDebouncethe delayed copy of the valuea timer, cleaned up
useLocalStoragethe current valuea write to localStorage

The shape of the state

// useDebounce — one piece of state: the lagging copy
const [debounced, setDebounced] = useState(value);
// value      → changes instantly (owned by the caller)
// debounced  → catches up `delay` ms after value stops moving

// useLocalStorage — one piece of state, seeded FROM storage
const [stored, setStored] = useState(() => read(key, initial));
// lazy fn → runs on first render only, so we don't hit disk every render
Rule of thumb React state is the source of truth for rendering; localStorage is a mirror we write to. Never read storage during render — read it once, then trust state.

Build it in layers

In an interview, build L1 and L2 first, out loud, then ask "want me to add the functional updater and error handling?"

L1 The dumbest version that works

A timer that sets the value later. No cleanup yet — it's wrong, and you'll say so.

function useDebounce(value, delay) {
  const [debounced, setDebounced] = useState(value);
  useEffect(() => {
    setTimeout(() => setDebounced(value), delay); // leaks!
  }, [value, delay]);
  return debounced;
}

L2 Cleanup — the whole trick

Every new keystroke cancels the previous timer. Only the last one survives.

useEffect(() => {
  const id = setTimeout(() => setDebounced(value), delay);
  return () => clearTimeout(id); // ← cancels on next change + unmount
}, [value, delay]);

L3 useLocalStorage — lazy read + write-through

Read storage once, then keep state and storage in sync on every set.

function useLocalStorage(key, initial) {
  const [value, setValue] = useState(() => {
    const raw = localStorage.getItem(key);
    return raw ? JSON.parse(raw) : initial; // stored as JSON
  });
  const set = (next) => {
    setValue(next);
    localStorage.setItem(key, JSON.stringify(next));
  };
  return [value, set];
}

Two holes left: set(v => !v) would store a function, and bad JSON throws.

L4 Functional updater + try/catch

Resolve the updater yourself so you know what you're writing; wrap every storage touch.

const set = useCallback((next) => {
  setValue(prev => {
    const val = typeof next === 'function' ? next(prev) : next; // ← unwrap
    try { window.localStorage.setItem(key, JSON.stringify(val)); } catch {}
    return val;
  });
}, [key]);
Why the try/catch Safari private mode and full quotas make setItem throw. On the server there is no window at all. Both crash the app without a guard.

The whole thing

import { useState, useEffect, useCallback } from 'react';

// ---- useDebounce: value that lags behind ----
export function useDebounce(value, delay = 500) {
  const [debounced, setDebounced] = useState(value);
  useEffect(() => {
    const id = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(id);
  }, [value, delay]);
  return debounced;
}

// ---- useLocalStorage: useState that persists ----
export function useLocalStorage(key, initial) {
  const [value, setValue] = useState(() => {
    try {
      const raw = window.localStorage.getItem(key);
      return raw === null ? initial : JSON.parse(raw);
    } catch {
      return initial; // no window, or corrupt JSON
    }
  });

  const set = useCallback((next) => {
    setValue(prev => {
      const val = typeof next === 'function' ? next(prev) : next;
      try { window.localStorage.setItem(key, JSON.stringify(val)); } catch {}
      return val;
    });
  }, [key]);

  return [value, set];
}

// ---- using them ----
function Search() {
  const [q, setQ] = useState('');
  const debouncedQ = useDebounce(q, 500);
  const [theme, setTheme] = useLocalStorage('theme', 'light');

  useEffect(() => {
    if (debouncedQ) fetch(`/api?q=${debouncedQ}`);
  }, [debouncedQ]); // → fires once per pause, not per keystroke

  return (
    <div data-theme={theme}>
      <input value={q} onChange={e => setQ(e.target.value)} />
      <button onClick={() => setTheme(t => t === 'light' ? 'dark' : 'light')}>
        Toggle
      </button>
    </div>
  );
}

Gotchas

Forgetting clearTimeout. Without it every keystroke fires its own timer — you debounced nothing. Return the cleanup.
Passing initial instead of a function to useState. useState(read()) hits storage on every render. useState(() => read()) hits it once.
Storing raw strings. getItem always returns a string, so true comes back as "true". Always JSON.stringify in, JSON.parse out.
Treating a missing key as falsy. if (raw) discards a legitimately stored 0, "" or false. Check raw === null.
Ignoring the functional form. setTheme(t => ...) would write the function itself into storage. Unwrap it inside the setter.

If they push

"Sync it across browser tabs."

The storage event fires in other tabs when a key changes.

useEffect(() => {
  const onStorage = (e) => {
    if (e.key !== key) return;
    try { setValue(e.newValue === null ? initial : JSON.parse(e.newValue)); } catch {}
  };
  window.addEventListener('storage', onStorage);
  return () => window.removeEventListener('storage', onStorage);
}, [key]);
"Debounce a function, not a value."

Different hook: useDebounce returns a lagging value; useDebouncedCallback returns a function you call.

function useDebouncedCallback(fn, delay) {
  const ref = useRef(fn);              // a ref — a box that survives re-renders
  useEffect(() => { ref.current = fn; });
  const timer = useRef();
  return useCallback((...args) => {
    clearTimeout(timer.current);
    timer.current = setTimeout(() => ref.current(...args), delay);
  }, [delay]);
}

Use the value version for search-as-you-type; the callback version for "save draft" or "resize handler".

"What about server-side rendering?"

The server render has no storage, so it uses initial — then the client render differs and React warns. Fix: render initial first, then swap in the stored value in a useEffect.

"Why not useDeferredValue?"

It de-prioritises a render, it doesn't wait a fixed time — good for laggy UI, no good for cutting network calls. Debounce is time-based; defer is priority-based.

"Fire immediately on the first call?"

That's throttle-leading behaviour: keep an isFirst ref and skip the timer on the initial run.

Say this out loud

  1. "A custom hook is just a function starting with use that calls other hooks — so I can lift this logic out and each component still gets its own state."
  2. "The debounce state is the lagging copy of the value; the effect owns the timer, and the cleanup cancels it — that cancel is the whole feature."
  3. "I'll pass a function to useState so we read localStorage exactly once instead of on every render."
  4. "Storage only holds strings, so everything goes through JSON.stringify and parse, inside a try/catch — private mode and corrupt values both throw."
  5. "I'll support setValue(prev => ...) so it's a drop-in replacement for useState."
  6. "If you want cross-tab sync I'd add a storage event listener, with a cleanup on unmount."

Styling here barely matters — hooks are scored on state, cleanup, and edge cases.
