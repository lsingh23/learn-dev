35. Debounced Search & Autocomplete

Type, pause, fetch once, show a dropdown. Tests timers, effect cleanup, and race conditions.

The ask

Interviewer "Build a search box that suggests results from an API as you type. Don't fire a request on every keystroke, and make sure the dropdown always shows the right thing."

It should:

  • Update the input on every keystroke.
  • Fire one request per pause, not per key.
  • Show a loading row while waiting.
  • Show "No results" when the list is empty.
  • Never show a stale response.
  • Hide the dropdown when the box is empty.
  • Support ↑ ↓ Enter Esc.

Styling barely matters here. They're scoring the timer, the cleanup, and the race.

The mental model

Typing is fast, the network is slow. Put a timer between them: every keystroke cancels the old timer and starts a new one. Only a gap of silence lets a request through.

In React, that timer lives in an effect. The effect's cleanup runs before the next one — so cleanup is the cancel.

The shape of the state

const [query,   setQuery]   = useState("");  // what's in the box, every keystroke
const [results, setResults] = useState([]);  // last response we accepted
const [loading, setLoading] = useState(false);// a request is in flight
const [open,    setOpen]    = useState(false);// is the dropdown showing
const [active,  setActive]  = useState(-1);  // highlighted row, -1 = none

Rule of thumb: query is the only thing the user edits. Everything else is a consequence of it — so it's the only effect dependency.

L3 Debounce + fetch + states

One effect owns the timer, the request, and the answer.

useEffect(() => {
  if (!query.trim()) { setResults([]); setLoading(false); return; }
  let ignore = false;
  setLoading(true);
  const id = setTimeout(async () => {
    const data = await fetch(`/api/search?q=${query}`).then(r => r.json());
    if (ignore) return;          // an older search — drop it
    setResults(data); setActive(-1); setLoading(false);
  }, 300);
  return () => { ignore = true; clearTimeout(id); };
}, [query]);
The race they're checking for. "reac" is slow, "react" is fast. Without ignore, the slow one lands last and you show reac's results under the word react. Cleanup flips the flag, so old responses are thrown away.

L4 Keyboard

Arrows move the highlight, Enter picks, Esc closes.

function onKeyDown(e) {
  if (!open || !results.length) return;
  if (e.key === "ArrowDown") setActive(i => (i + 1) % results.length);
  else if (e.key === "ArrowUp") setActive(i => (i - 1 + results.length) % results.length);
  else if (e.key === "Enter" && active >= 0) pick(results[active]);
  else if (e.key === "Escape") setOpen(false);
  else return;
  e.preventDefault();   // stop the caret jumping / form submitting
}

The whole thing

function Autocomplete() {
  const [query, setQuery] = useState("");
  const [results, setResults] = useState([]);
  const [loading, setLoading] = useState(false);
  const [open, setOpen] = useState(false);
  const [active, setActive] = useState(-1);

  useEffect(() => {
    if (!query.trim()) { setResults([]); setLoading(false); return; }
    let ignore = false;
    setLoading(true);
    const id = setTimeout(async () => {
      const res = await fetch(`/api/search?q=${encodeURIComponent(query)}`);
      const data = await res.json();
      if (ignore) return;
      setResults(data); setActive(-1); setLoading(false);
    }, 300);
    return () => { ignore = true; clearTimeout(id); };
  }, [query]);

  const pick = (item) => { setQuery(item.name); setOpen(false); };

  function onKeyDown(e) {
    if (!open || !results.length) return;
    if (e.key === "ArrowDown") setActive(i => (i + 1) % results.length);
    else if (e.key === "ArrowUp") setActive(i => (i - 1 + results.length) % results.length);
    else if (e.key === "Enter" && active >= 0) pick(results[active]);
    else if (e.key === "Escape") setOpen(false);
    else return;
    e.preventDefault();
  }

  return (
    <div className="search">
      <input
        value={query} placeholder="Search…"
        role="combobox" aria-expanded={open} aria-autocomplete="list"
        onChange={e => { setQuery(e.target.value); setOpen(true); }}
        onFocus={() => setOpen(true)}
        onBlur={() => setOpen(false)}
        onKeyDown={onKeyDown}
      />
      {open && query.trim() && (
        <ul role="listbox">
          {loading && <li>Searching…</li>}
          {!loading && results.length === 0 && <li>No results</li>}
          {!loading && results.map((r, i) => (
            <li key={r.id} role="option" aria-selected={i === active}
                className={i === active ? "on" : ""}
                onMouseDown={() => pick(r)}>{r.name}</li>
          ))}
        </ul>
      )}
    </div>
  );
}

Gotchas

No cleanup on the timer. Every keystroke leaves a live setTimeout — you get the un-debounced behaviour plus five renders. Always return () => clearTimeout(id).
Ignoring the stale response. Responses come back out of order. ignore flag, or AbortController. Say the words "race condition" out loud.
onClick on the dropdown row. onBlur fires first and unmounts the list, so the click never lands. Use onMouseDown.
Stale results left on screen. Clear the input → clear results, or the old list flashes back on next focus.
Debouncing the wrong thing. Don't debounce setQuery — the input must feel instant. Debounce the fetch.

If they push

"Use AbortController instead." Same cleanup slot, and it actually cancels the network call. 
const c = new AbortController();
fetch(url, { signal: c.signal }).catch(e => { if (e.name !== "AbortError") throw e; });
return () => { c.abort(); clearTimeout(id); };
"Extract a useDebounce hook." useDebounce(value, 300) holds a state copy updated inside the same timer effect, and returns it. Then the fetch effect depends on the debounced value.
"Cache repeat searches." A useRef(new Map()) keyed by query. Hit the cache → render instantly, skip the fetch. A ref, not state — writing to it shouldn't re-render.
"1000 suggestions." Cap it server-side (limit=10) — that's the real fix. If the list must be long, windowing so only visible rows are in the DOM.
"Make it accessible." role="combobox" + aria-expanded on the input, role="listbox"/"option" on the list, and aria-activedescendant pointing at the highlighted row's id — focus stays in the input.

Say this out loud

  • "The input stays instant — I'm only delaying the network call."
  • "The timer lives in an effect keyed on the query, and the cleanup cancels it. That's the whole debounce."
  • "Responses can land out of order, so I'll guard with an ignore flag — or abort the old request."
  • "Three render states here: loading, results, and empty. I don't want a blank dropdown."
  • "I'll use mouseDown rather than click, because blur closes the list first."
  • "Keyboard's expected on a combobox, so arrows and Enter, and I'd add aria-activedescendant."
