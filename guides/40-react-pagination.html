40. Pagination

A table plus page buttons. One number in state; everything else is a slice.

The ask

Interviewer "Here's an array of 200 users. Render them in a table, 10 per page, with Prev / Next and numbered page buttons."

Show a window of a big list, and let the user move the window.

What we're building

Paginated table — page 4 of 20
Search name… changing this resets page → 1
#NameEmail
31Ada Lovelaceada@mail.com
32Alan Turingalan@mail.com
33Grace Hoppergrace@mail.com
34Ken Thompsonken@mail.com
… 6 more rows …
‹ Prev 1 … 3 4 5 … 20 Next ›

Showing 31–40 of 200

only page is state rows = slice of the array Prev disabled on page 1

It should:

  • Show 10 rows per page.
  • Prev / Next move one page.
  • Disable Prev on first, Next on last.
  • Highlight the current page number.
  • Reset to page 1 when the filter changes.
  • Show "Showing 31–40 of 200".

The mental model

The page number is a window sliding over one array. You never store the rows — you cut them fresh on every render.

page = 2, perPage = 4 → slice(4, 8)
0123 4567 891011

start = (page - 1) * perPage → (2-1)*4 = 4
rows.slice(start, start + perPage) → indexes 4,5,6,7

click "3"→ page = 3→ slice(8, 12)→ table re-renders

totalPages = Math.ceil(total / perPage) — 200 / 10 = 20. 201 items? ceil gives 21.

The shape of the state

const [page, setPage] = useState(1);   // the ONLY state. 1-based.
const [query, setQuery] = useState("");    // optional filter
const perPage = 10;                        // constant (or state if user picks it)

// everything below is DERIVED, not stored:
const filtered   = rows.filter(r => r.name.includes(query));
const totalPages = Math.ceil(filtered.length / perPage) || 1;
const start      = (page - 1) * perPage;
const visible    = filtered.slice(start, start + perPage);
Rule of thumb One source of truth — derive the rest. Storing visibleRows in state means two things can disagree.

Build it in layers

In an interview, build L1 and L2 out loud first, then ask "want me to add numbered pages / server-side?"

L1 Dumbest thing that renders

All rows, no state.

function Table({ rows }) {
  return (
    <table><tbody>
      {rows.map(r => <tr key={r.id}><td>{r.name}</td></tr>)}
    </tbody></table>
  );
}

L2 One page + Prev / Next

Add page, slice, clamp the buttons.

const [page, setPage] = useState(1);
const totalPages = Math.ceil(rows.length / perPage) || 1;
const visible = rows.slice((page - 1) * perPage, page * perPage);

<button onClick={() => setPage(p => p - 1)} disabled={page === 1}>Prev</button>
<span>{page} / {totalPages}</span>
<button onClick={() => setPage(p => p + 1)} disabled={page === totalPages}>Next</button>

L3 Number buttons + reset on filter

Render 1..totalPages; any filter change snaps back to page 1.

{Array.from({ length: totalPages }, (_, i) => i + 1).map(n => (
  <button key={n} aria-current={n === page ? "page" : undefined}
          onClick={() => setPage(n)}>{n}</button>
))}

// reset where the filter changes — not in an effect
function onSearch(v) { setQuery(v); setPage(1); }

L4 Windowed strip: 1 … 4 5 6 … 20

20 buttons is fine. 500 is not — show neighbours plus the ends.

function pageItems(page, total, span = 1) {
  const set = new Set([1, total]);
  for (let i = page - span; i <= page + span; i++)
    if (i > 1 && i < total) set.add(i);
  const nums = [...set].sort((a, b) => a - b);
  return nums.flatMap((n, i) =>
    i && n - nums[i - 1] > 1 ? ["…", n] : [n]);   // → [1,"…",4,5,6,"…",20]
}

The whole thing

function PaginatedTable({ rows, perPage = 10 }) {
  const [page, setPage] = useState(1);
  const [query, setQuery] = useState("");

  const filtered = useMemo(
    () => rows.filter(r => r.name.toLowerCase().includes(query.toLowerCase())),
    [rows, query]
  );
  const totalPages = Math.max(1, Math.ceil(filtered.length / perPage));
  const safePage = Math.min(page, totalPages);
  const start = (safePage - 1) * perPage;
  const visible = filtered.slice(start, start + perPage);

  return (
    <div>
      <input value={query} placeholder="Search name…"
             onChange={e => { setQuery(e.target.value); setPage(1); }} />

      <table>
        <thead><tr><th>Name</th><th>Email</th></tr></thead>
        <tbody>
          {visible.map(r => (
            <tr key={r.id}><td>{r.name}</td><td>{r.email}</td></tr>
          ))}
          {!visible.length && <tr><td colSpan={2}>No results</td></tr>}
        </tbody>
      </table>

      <nav aria-label="Pagination">
        <button onClick={() => setPage(p => p - 1)} disabled={safePage === 1}>
          ‹ Prev
        </button>
        {pageItems(safePage, totalPages).map((it, i) =>
          it === "…"
            ? <span key={"d" + i}>…</span>
            : <button key={it} onClick={() => setPage(it)}
                      aria-current={it === safePage ? "page" : undefined}>{it}</button>
        )}
        <button onClick={() => setPage(p => p + 1)} disabled={safePage === totalPages}>
          Next ›
        </button>
      </nav>

      <p>Showing {filtered.length ? start + 1 : 0}–{start + visible.length} of {filtered.length}</p>
    </div>
  );
}

Styling barely matters here. Logic and layout are what's scored.

Gotchas

Off-by-one in the slice. Pages are 1-based, arrays are 0-based. Always (page - 1) * perPage, never page * perPage as the start.
Stranded on an empty page. Filter to 5 results while on page 12 → blank table. Reset to 1 on filter change, and clamp with Math.min(page, totalPages).
totalPages = 0 when the list is empty. Math.ceil(0/10) is 0, so "1 / 0" renders. Wrap in Math.max(1, …).
Storing the sliced rows in state. Then rows go stale when the data or filter updates. Derive on every render; useMemo only if the filter is heavy.
Using the array index as the key. Indexes restart at 0 on each page, so React reuses rows wrongly. Key by r.id.

If they push

"Now it's 1,000,000 rows from an API." Move to server-side: the server owns the slice. Send ?offset={(page-1)*perPage}&limit={perPage} (or ?page=&size=) and the response carries { items, total }. Same formula, computed on the backend. 
useEffect(() => {
  const c = new AbortController();
  fetch(`/api/users?offset=${(page-1)*perPage}&limit=${perPage}`, { signal: c.signal })
    .then(r => r.json()).then(d => { setItems(d.items); setTotal(d.total); });
  return () => c.abort();          // kill stale page responses
}, [page, query]);
"Let the user pick 10 / 25 / 50 per page." perPage becomes state, and changing it must setPage(1) — otherwise page 20 of 10-per-page is off the end at 50-per-page.
"Keep the page in the URL." Read ?page= from the query string as the source of truth and push on click. Refresh and back-button then work for free.
"The feed is infinite / real-time." Offset pagination duplicates and skips rows when items are inserted. Use a cursor — ?after=<lastId> — and Next only, no jumping to page 7.
"Make it accessible." Wrap in <nav aria-label="Pagination">, mark the current button aria-current="page", use real <button>s so they're tabbable, and disabled (not hidden) at the ends.

Say this out loud

  • "The only state is the page number — the visible rows are just a slice, so they can't go stale."
  • "Start is (page - 1) * perPage because pages are 1-based and arrays are 0-based."
  • "Total pages is ceil(total / perPage), floored at 1 so an empty list still reads 1 of 1."
  • "I reset to page 1 in the search handler, so filtering can't leave you on an empty page."
  • "I'll disable Prev and Next at the ends rather than hide them, so the layout doesn't jump."
  • "If this were server-driven I'd send offset and limit and let the API return the total."
