38. Tabs

One state value, one find(). The whole test is whether you store the right thing.

The ask

Interviewer "Build a Tabs component. It takes an array of { id, label, content } and shows one panel at a time. Clicking a tab switches the panel."

Plain English: highlight one button, show the matching content.

What we're building

Tabs — 3 items, second one active

↑ the strip role="tablist" — one button per item in the array

↑ the panel role="tabpanel" — content of the found tab, nothing else rendered
↑ click or ← → keys change activeId

It should:

  • Render one button per array item.
  • Show exactly one panel at a time.
  • Highlight the active tab.
  • Switch on click.
  • Move with arrow keys.
  • Announce itself correctly to screen readers.

Styling barely matters here. Logic and markup are what's scored.

The mental model

You store which tab is open — a string. Everything on screen is computed from it.

One source of truth The active tab object is not state — it's a find() away. Store the id; derive the rest.

The shape of the state

// props — the data drives everything
tabs = [{ id: 'overview', label: 'Overview', content: … }, …]

// state — exactly one value
const [activeId, setActiveId] = useState(tabs[0].id);
//     ^ which tab is open. A string id, not an index, not the object.

// derived — recomputed each render, free
const active = tabs.find(t => t.id === activeId);

Why an id, not an index?

If you storeWhat breaks
activeIndex = 1Reorder or remove a tab and the wrong panel opens. Index means "second thing", not "Reviews".
activeTab = {…}The object goes stale when tabs updates. Two truths, one screen.
activeId = 'reviews'Nothing. It's a stable name and it survives reorders.

Build it in layers

In the interview Build L1 and L2 out loud — that's a working Tabs in about ten lines. Then stop and ask: "want me to add keyboard nav and ARIA?"

L1 Static markup, no state

The dumbest thing that renders. Prove the shape first.

function Tabs({ tabs }) {
  return (
    <div>
      <div className="strip">
        {tabs.map(t => <button key={t.id}>{t.label}</button>)}
      </div>
      <div className="panel">{tabs[0].content}</div>
    </div>
  );
}

L2 One state value + find()

Adds switching. This is already a correct answer.

L3 ARIA roles

Three roles and three attributes. Free points.

<div role="tablist">
  <button role="tab" id={`tab-${t.id}`}
    aria-selected={t.id === activeId}
    aria-controls={`panel-${t.id}`}>{t.label}</button>
</div>
<div role="tabpanel" id={`panel-${active.id}`}
     aria-labelledby={`tab-${active.id}`} tabIndex={0}>
  {active.content}
</div>

L4 Arrow keys + roving tabindex

Roving tabindex — only the active tab is Tab-reachable; arrows move between tabs.

const move = (dir) => {
  const i = tabs.findIndex(t => t.id === activeId);
  const next = tabs[(i + dir + tabs.length) % tabs.length]; // wraps
  setActiveId(next.id);
  document.getElementById(`tab-${next.id}`)?.focus();      // focus follows
};

onKeyDown={(e) => {
  if (e.key === 'ArrowRight') move(1);
  if (e.key === 'ArrowLeft')  move(-1);
  if (e.key === 'Home') setActiveId(tabs[0].id);
  if (e.key === 'End')  setActiveId(tabs.at(-1).id);
}}
// on each button: tabIndex={t.id === activeId ? 0 : -1}

The whole thing

import { useState } from 'react';

export default function Tabs({ tabs, defaultId }) {
  const [activeId, setActiveId] = useState(defaultId ?? tabs[0]?.id);
  const active = tabs.find(t => t.id === activeId) ?? tabs[0];

  const move = (dir) => {
    const i = tabs.findIndex(t => t.id === active.id);
    const next = tabs[(i + dir + tabs.length) % tabs.length];
    setActiveId(next.id);
    document.getElementById(`tab-${next.id}`)?.focus();
  };

  const onKeyDown = (e) => {
    const k = e.key;
    if (k === 'ArrowRight') { e.preventDefault(); move(1); }
    else if (k === 'ArrowLeft') { e.preventDefault(); move(-1); }
    else if (k === 'Home') { e.preventDefault(); setActiveId(tabs[0].id); }
    else if (k === 'End') { e.preventDefault(); setActiveId(tabs.at(-1).id); }
  };

  if (!tabs?.length) return null;

  return (
    <div className="tabs">
      <div role="tablist" aria-label="Sections" onKeyDown={onKeyDown}>
        {tabs.map(t => {
          const on = t.id === active.id;
          return (
            <button
              key={t.id}
              id={`tab-${t.id}`}
              role="tab"
              type="button"
              aria-selected={on}
              aria-controls={`panel-${t.id}`}
              tabIndex={on ? 0 : -1}
              className={on ? 'tab on' : 'tab'}
              onClick={() => setActiveId(t.id)}
            >
              {t.label}
            </button>
          );
        })}
      </div>

      <div
        role="tabpanel"
        id={`panel-${active.id}`}
        aria-labelledby={`tab-${active.id}`}
        tabIndex={0}
      >
        {active.content}
      </div>
    </div>
  );
}

Gotchas

Storing the tab object in state. It goes stale the moment tabs changes. Store activeId, derive with find().
Storing an index. Reorder or delete a tab and the panel silently switches. Ids are stable, positions are not.
Assuming find() found something. The open tab can be removed. Fall back: ?? tabs[0], and handle an empty array.
<div> instead of <button> for a tab. No focus, no Enter/Space, no announcement. Always a real <button type="button">.
Every tab left in the tab order. A tablist is one stop, not five. Roving tabindex: 0 on the active tab, -1 on the rest.

If they push

"Render all panels and hide the inactive ones instead?"

Trade-off. Rendering only the active one unmounts the others — they lose their state (a half-typed form, a scroll position). Keep them mounted with hidden when that matters:

{tabs.map(t => (
  <div key={t.id} role="tabpanel" hidden={t.id !== activeId}>{t.content}</div>
))}
// hidden, not display:none in a class — screen readers respect it

Cost: all panels mount up front. Default to active-only; switch when losing state hurts.

"Make it controlled."

Support both: use the prop when given, internal state when not.

const [inner, setInner] = useState(defaultId ?? tabs[0].id);
const activeId = value ?? inner;                // controlled if `value` passed
const select = (id) => { setInner(id); onChange?.(id); };
"The panel is expensive — don't build it until it's opened."

Lazy-mount: remember which tabs have ever been visited, render only those.

const [seen, setSeen] = useState(() => new Set([activeId]));
// on select: setSeen(s => new Set(s).add(id))  — new Set, or React won't re-render
{tabs.filter(t => seen.has(t.id)).map(...)}
"Put the active tab in the URL."

Then the URL is the state — drop useState and read the query param. Refresh and share now work.

const [params, setParams] = useSearchParams();
const activeId = params.get('tab') ?? tabs[0].id;
const select = (id) => setParams({ tab: id }, { replace: true });
// replace: true so tab clicks don't spam the back button
"Twenty tabs, they overflow."

Horizontal scroll on the tablist, plus scrollIntoView on the newly active tab so keyboard nav never lands off-screen.

Say this out loud

  1. "There's really one piece of state here — which tab is open — so I'll hold activeId."
  2. "I'm storing the id rather than an index, so reordering the tabs can't open the wrong panel."
  3. "The active tab object is derived with a find(), not stored — one source of truth."
  4. "I'll render only the active panel. If panels held form state I'd keep them all mounted and use hidden instead."
  5. "These are real buttons in a tablist, with roving tabindex so the whole strip is one tab stop."
  6. "Want it controlled, or the active tab synced to the URL? Both are small changes from here."
