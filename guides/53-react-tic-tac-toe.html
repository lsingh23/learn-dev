53. Tic-Tac-Toe

The classic warm-up. It's really a test of one thing: can you pick the right data shape?

The ask

Interviewer "Build tic-tac-toe. Two players share the mouse, X goes first. Show who won, handle a draw, and add a reset button."

Nine squares. Click fills one. After every click, ask: did someone win yet?

It should:

  • Render 9 squares in a 3×3 grid.
  • Alternate X and O on click.
  • Ignore clicks on filled squares.
  • Announce a winner and freeze the board.
  • Announce a draw when full, no winner.
  • Reset to an empty board.

Styling barely matters here. Grid + logic is what's scored.

The mental model

The board is a flat array of 9, not a 2D array. Indexes 0…8 read left-to-right, top-to-bottom. CSS grid handles the 2D-ness for free, so your JS never needs a row/column.

And now the payoff — the whole game in one picture. Every way to win is three indexes:

The 8 winning lines, drawn over the index grid
rows: [0,1,2] [3,4,5] [6,7,8] cols: [0,3,6] [1,4,7] [2,5,8] diagonals: [0,4,8] [2,4,6]

Hard-code those 8 triples as a constant. Winning is then: is any triple three of the same non-null value?

The shape of the state

const [squares, setSquares] = useState(Array(9).fill(null));
// 9 slots, each 'X' | 'O' | null. The only real state.

const [isXNext, setIsXNext] = useState(true);
// whose turn. See note below — you can also derive this.
One source of truth — derive the rest.

Winner, draw and status are computed during render, never stored. Storing them means two places to keep in sync, and that's where bugs live.

Two ways to know whose turn it is. Both are fine; say the trade-off out loud:

// A) a boolean — simple, but a second piece of state to keep in sync
const player = isXNext ? 'X' : 'O';

// B) derive from move count — zero extra state, cannot desync
const moves = squares.filter(Boolean).length;
const player = moves % 2 === 0 ? 'X' : 'O';   // → even = X's turn

B is the tidier answer. A is the one React's own tutorial uses, and it's what you want later for time travel.

Build it in layers

In an interview: build L1 and L2 first, out loud.

Then say “that's a playable board — want me to add win detection, or reset first?” You get credit for sequencing.

L1 A static grid

Dumbest thing that renders. No state.

<div className="board">
  {Array(9).fill(null).map((_, i) => (
    <button key={i} className="sq">{null}</button>
  ))}
</div>

.board { display:grid; grid-template-columns:repeat(3,64px); gap:6px }

L2 Clicking alternates X and O

State in, plus the guard for an already-taken square.

const [squares, setSquares] = useState(Array(9).fill(null));
const player = squares.filter(Boolean).length % 2 === 0 ? 'X' : 'O';

function handleClick(i) {
  if (squares[i]) return;              // taken — ignore
  const next = squares.slice();        // copy, never mutate
  next[i] = player;
  setSquares(next);
}

L3 Win detection

The 8 lines, checked top to bottom. Returns the mark, or null.

const LINES = [
  [0,1,2],[3,4,5],[6,7,8],   // rows
  [0,3,6],[1,4,7],[2,5,8],   // cols
  [0,4,8],[2,4,6],           // diagonals
];

function calculateWinner(sq) {
  for (const [a, b, c] of LINES) {
    if (sq[a] && sq[a] === sq[b] && sq[a] === sq[c]) return sq[a];
  }
  return null;                         // → 'X' | 'O' | null
}

Declare LINES outside the component — it never changes, so don't rebuild it each render.

L4 Status, draw, freeze, reset

All derived. One extra clause on the click guard.

const winner = calculateWinner(squares);
const isDraw = !winner && squares.every(Boolean);   // full + nobody won

const status = winner   ? `Winner: ${winner}`
             : isDraw   ? "It's a draw"
             :            `Next player: ${player}`;

if (squares[i] || winner) return;      // in handleClick: freeze after a win

<button onClick={() => setSquares(Array(9).fill(null))}>Reset</button>

The whole thing

const LINES = [[0,1,2],[3,4,5],[6,7,8],[0,3,6],[1,4,7],[2,5,8],[0,4,8],[2,4,6]];

function calculateWinner(sq) {
  for (const [a, b, c] of LINES) {
    if (sq[a] && sq[a] === sq[b] && sq[a] === sq[c]) return sq[a];
  }
  return null;
}

export default function TicTacToe() {
  const [squares, setSquares] = useState(Array(9).fill(null));

  const winner = calculateWinner(squares);
  const isDraw = !winner && squares.every(Boolean);
  const player = squares.filter(Boolean).length % 2 === 0 ? 'X' : 'O';
  const status = winner ? `Winner: ${winner}`
               : isDraw ? "It's a draw"
               : `Next player: ${player}`;

  function handleClick(i) {
    if (squares[i] || winner) return;
    const next = squares.slice();
    next[i] = player;
    setSquares(next);
  }

  return (
    <div>
      <p aria-live="polite">{status}</p>

      <div className="board" role="grid">
        {squares.map((value, i) => (
          <button
            key={i}
            className="sq"
            onClick={() => handleClick(i)}
            aria-label={`Square ${i + 1}${value ? `, ${value}` : ', empty'}`}
          >
            {value}
          </button>
        ))}
      </div>

      <button onClick={() => setSquares(Array(9).fill(null))}>Reset</button>
    </div>
  );
}

Gotchas

Mutating the array. squares[i] = player; setSquares(squares) is the same reference — React skips the re-render. Always .slice() first.
Forgetting to freeze after a win. Without || winner in the guard, players keep filling squares under a "Winner: X" banner.
Draw checked before winner. A board can be full and won on the last move. Compute winner first, then isDraw = !winner && full.
Storing the winner in state. Now you need an effect to keep it fresh, and reset has one more thing to clear. Derive it.
squares.every(Boolean) vs .length === 9. The array is always length 9. Fullness means no nulls left.

If they push

“Make it N×N, win with K in a row.”

Stop hard-coding lines — generate them, or check only through the square just played. Walk out in 4 directions from that index and count.

const rows = Math.floor(i / N), col = i % N;
// for each of →, ↓, ↘, ↙ : count matching marks both ways, +1 for self
// any direction reaching K wins. O(N) per move instead of O(N²).
“Add undo / time travel.”

Store history — an array of boards — plus a step index. squares = history[step]. Jumping back is setStep(n); a new move slices off the future.

const [history, setHistory] = useState([Array(9).fill(null)]);
const [step, setStep] = useState(0);
const squares = history[step];
setHistory([...history.slice(0, step + 1), next]);

Here the derived-turn trick shines: step % 2 === 0 ? 'X' : 'O'.

“Highlight the winning line.”

Return the line, not just the mark: return { player: sq[a], line: [a,b,c] }. Then className={line?.includes(i) ? 'sq win' : 'sq'}.

“Play against the computer.”

Start dumb — pick a random empty index after each human move, in an effect or right inside handleClick.

const open = squares.map((v, i) => v === null ? i : null).filter(v => v !== null);
const move = open[Math.floor(Math.random() * open.length)];

Then one step up: block if the opponent has two in a line. Unbeatable is minimax — score every leaf +1/0/−1 and alternate max/min; mention it, only write it if asked.

“Keyboard accessible?”

Already is, because each square is a <button>. Add aria-live="polite" on the status so a screen reader announces the winner, and disabled on filled squares.

Say this out loud

  • “I'll keep the board as a flat array of nine — CSS grid gives me the 2D layout, so my logic never deals with rows and columns.”
  • “There are only eight ways to win, so I'll hard-code them as index triples outside the component and loop them after each move.”
  • “Winner, draw and whose-turn are all derived from the board during render — one source of truth, nothing to keep in sync.”
  • “I'm copying the array before setting it, otherwise React sees the same reference and won't re-render.”
  • “Two guards on a click: square already taken, or the game is already won.”
  • “Squares are real buttons with aria-labels, and the status has aria-live so it's announced.”
