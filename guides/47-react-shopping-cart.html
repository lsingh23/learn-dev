47. Shopping Cart

Scores one thing above all: do you store a reference, or a copy?

The ask

Interviewer “Here’s a list of products. Let me add them to a cart, change the quantity, remove things, and show me the running total.”

Two lists on screen, one array in state, one number derived from it.

What we're building

↑ Total not stored anywhere — recomputed every render.
↑ Empty cart shows “Your cart is empty”, total $0.00.

It should:

  • List products with name and price.
  • Add to cart; duplicates bump quantity.
  • + / − adjust quantity per line.
  • Removing at qty 1 deletes the row.
  • Show a running total, always correct.
  • Show an empty state.

Styling barely matters here. State shape and immutable updates are the score.

The mental model

The cart does not hold products. It holds tickets: an id and a quantity. Prices live in exactly one place — the product list — and the cart points at them.

Why not copy the product into the cart? Because then a price lives in two places. Change it once and the cart is stale. Store the id; look the product up when you render.

The shape of the state

// data, not state — it never changes, so it lives outside the component
const PRODUCTS = [
  { id: 1, name: 'Espresso',  price: 3.50 },
  { id: 2, name: 'Croissant', price: 4.25 },
  { id: 3, name: 'Cookie',    price: 2.00 },
];

// the ONLY state. one line per distinct product in the cart.
const [cart, setCart] = useState([]);
// → [{ id: 1, qty: 2 }, { id: 3, qty: 1 }]
//     id  = which product (a pointer, not a copy)
//     qty = how many. qty is never 0 — a 0 row gets deleted.
Rule of thumb One source of truth — derive the rest. Total, item count and “is this in the cart?” are all computed from cart, never stored beside it.

A lookup map saves you a find() on every row:

const BY_ID = Object.fromEntries(PRODUCTS.map(p => [p.id, p]));
// BY_ID[1].price → 3.5

Build it in layers

In the interview Build L1 and L2 out loud, get something on screen, then ask “want me to add quantities, or persistence?” Don’t silently write all four.

L1 Static markup, zero state

Prove the products render. Nothing is clickable yet.

function Shop() {
  return (
    <ul>
      {PRODUCTS.map(p => (
        <li key={p.id}>{p.name} — ${p.price.toFixed(2)}
          <button>Add</button>
        </li>
      ))}
    </ul>
  );
}

L2 Add to cart — the line they’re watching for

Existing line? bump it. New? append it. Never push a duplicate.

const [cart, setCart] = useState([]);

function add(id) {
  setCart(c =>
    c.some(i => i.id === id)
      ? c.map(i => i.id === id ? { ...i, qty: i.qty + 1 } : i)
      : [...c, { id, qty: 1 }]
  );
}

Then render the cart by looking each id up:

{cart.map(i => (
  <li key={i.id}>{BY_ID[i.id].name} × {i.qty}</li>
))}

L3 Quantity ± and remove

One function does both: map to change, filter to drop the zeros.

function changeQty(id, delta) {
  setCart(c =>
    c.map(i => i.id === id ? { ...i, qty: i.qty + delta } : i)
     .filter(i => i.qty > 0)   // qty hit 0 → row disappears
  );
}

const remove = id => setCart(c => c.filter(i => i.id !== id));

L4 The derived total

Plain variables in the render body. No useState, no useEffect.

const total = cart.reduce(
  (sum, i) => sum + BY_ID[i.id].price * i.qty, 0
);
const count = cart.reduce((n, i) => n + i.qty, 0);
// → total 9, count 3

The whole thing

const PRODUCTS = [
  { id: 1, name: 'Espresso', price: 3.5 },
  { id: 2, name: 'Croissant', price: 4.25 },
  { id: 3, name: 'Cookie', price: 2 },
];
const BY_ID = Object.fromEntries(PRODUCTS.map(p => [p.id, p]));
const money = n => n.toFixed(2);

export default function Cart() {
  const [cart, setCart] = useState([]);

  const add = id => setCart(c =>
    c.some(i => i.id === id)
      ? c.map(i => (i.id === id ? { ...i, qty: i.qty + 1 } : i))
      : [...c, { id, qty: 1 }]);

  const changeQty = (id, d) => setCart(c =>
    c.map(i => (i.id === id ? { ...i, qty: i.qty + d } : i))
     .filter(i => i.qty > 0));

  const total = cart.reduce((s, i) => s + BY_ID[i.id].price * i.qty, 0);

  return (
    <div>
      <h2>Products</h2>
      <ul>
        {PRODUCTS.map(p => (
          <li key={p.id}>
            {p.name} — ${money(p.price)}
            <button onClick={() => add(p.id)}>Add</button>
          </li>
        ))}
      </ul>

      <h2>Cart</h2>
      {cart.length === 0 ? (
        <p>Your cart is empty.</p>
      ) : (
        <ul>
          {cart.map(i => {
            const p = BY_ID[i.id];
            return (
              <li key={i.id}>
                {p.name}
                <button onClick={() => changeQty(i.id, -1)}
                        aria-label={`Remove one ${p.name}`}>−</button>
                <span>{i.qty}</span>
                <button onClick={() => changeQty(i.id, 1)}
                        aria-label={`Add one ${p.name}`}>+</button>
                ${money(p.price * i.qty)}
                <button onClick={() => changeQty(i.id, -i.qty)}>×</button>
              </li>
            );
          })}
        </ul>
      )}
      <p><b>Total: ${money(total)}</b></p>
    </div>
  );
}

Gotchas

Pushing a duplicate row on second Add. Check some(i => i.id === id) first. Two “Espresso” rows is the classic fail.
Copying the whole product into the cart. {...product, qty:1} duplicates the price. Store {id, qty} and look it up.
Keeping total in state. A second source of truth that drifts. Compute it in the render body with reduce.
Mutating the cart. item.qty++ or cart.push(...) changes the same array — React sees no new reference and skips the re-render. Always map/filter/spread.
Letting quantity go to 0 or negative. Filter qty > 0 right after the map, so 0 removes the row in one step.

If they push

“That’s a lot of setCart calls — tidy it up.”

Move the rules into a useReducer. Actions read like the UI, and the logic is testable without React.

function cartReducer(cart, action) {
  switch (action.type) {
    case 'add':
      return cart.some(i => i.id === action.id)
        ? cart.map(i => i.id === action.id ? { ...i, qty: i.qty + 1 } : i)
        : [...cart, { id: action.id, qty: 1 }];
    case 'changeQty':
      return cart.map(i => i.id === action.id
                ? { ...i, qty: i.qty + action.delta } : i)
                .filter(i => i.qty > 0);
    case 'remove': return cart.filter(i => i.id !== action.id);
    case 'clear':  return [];
    default: return cart;
  }
}

const [cart, dispatch] = useReducer(cartReducer, []);
// dispatch({ type: 'add', id: 1 })
“The header needs a cart badge.”

Context, so you don’t thread props through the layout.

const CartCtx = createContext(null);

<CartCtx.Provider value={{ cart, dispatch }}>…</CartCtx.Provider>

// in Header, derive the number where it's used:
const { cart } = useContext(CartCtx);
const count = cart.reduce((n, i) => n + i.qty, 0);
“Keep the cart across refreshes.”

Lazy initial state to read, one effect to write.

const [cart, setCart] = useState(() =>
  JSON.parse(localStorage.getItem('cart') || '[]'));

useEffect(() => {
  localStorage.setItem('cart', JSON.stringify(cart));
}, [cart]);

Storing only {id, qty} pays off here — prices are never stale on reload.

“Format the money properly.” 
const fmt = new Intl.NumberFormat('en-US',
  { style: 'currency', currency: 'USD' });
fmt.format(9);  // → "$9.00"

Build the formatter once outside the component, not per render. For real money, keep prices in cents (integers) and divide only when displaying.

“Products come from an API.”

Nothing about the cart changes — that’s the payoff of storing ids. Fetch into products state, build byId with useMemo, and guard the lookup for a product that vanished.

Say this out loud

  • “The cart stores ids and quantities, not copies of the products — so the price lives in one place.”
  • “Add checks whether the item is already in the cart; if it is I bump qty instead of pushing a duplicate.”
  • “The total is derived with reduce on every render. I’m deliberately not keeping it in state.”
  • “Every update is a new array — map and filter, no mutation — so React re-renders.”
  • “Decrementing to zero filters the row out, so I never show a qty-0 line.”
  • “The +/− buttons get aria-labels naming the product, otherwise a screen reader just hears ‘plus, plus, plus’.”
  • “If this grew, I’d move these updates into a reducer and expose the cart through context.”
