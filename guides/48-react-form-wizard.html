48. Multi-Step Form Wizard

Three screens, one form. It tests whether you keep state in one place.

The ask

Interviewer "Build a 3-step signup form with a progress indicator. Back and Next between steps, validate each step before moving on, and submit at the end."

Plain English: one object holds every answer, and a number says which slice of it you're looking at.

What we're building

↑ dots come from the same steps array that picks the screen

↑ Next is blocked until this step validates
↑ last step's button says Submit, not Next

It should:

  • Show which step you're on.
  • Keep typed values when you go Back.
  • Block Next on invalid fields.
  • Show errors only after you try.
  • Hide Back on step 1.
  • Submit the whole form at the end.

Styling barely matters here. Logic and state layout are what's scored.

The mental model

Not three forms. One form, revealed a third at a time. The inputs unmount when you change step — the data must live above them, so it survives.

The whole trick step chooses what to render. It never chooses what to store.

The shape of the state

const [step, setStep] = useState(0);      // which screen — a number, nothing more
const [data, setData] = useState({        // every answer from every step, in one bag
  email:"", password:"", name:"", age:"", plan:"free"
});
const [errors, setErrors] = useState({}); // { age: "Must be 18 or older" }
const [tried, setTried] = useState(false);// has Next been pressed on this step?

Rule of thumb: one source of truth, derive the rest. Progress, button labels, "is this the last step" — all computed from step at render time.

// derived, NOT state:
const isLast  = step === steps.length - 1;
const percent = (step / (steps.length - 1)) * 100;

Build it in layers

In an interview Build L1 and L2 out loud first. Then say: "shared state next, then validation — want me to keep going?"

L1 Static markup, no state

Get one screen on the page. Prove the layout.

function Wizard(){
  return (
    <div className="card">
      <h2>Account</h2>
      <input placeholder="Email" />
      <input placeholder="Password" />
      <button>Next</button>
    </div>
  );
}

L2 A steps config + step

One array feeds both the dots and the body. Adding a step is now a one-line change.

const steps = [
  { id:"account", title:"Account" },
  { id:"profile", title:"Profile" },
  { id:"plan",    title:"Plan"    },
];

const [step, setStep] = useState(0);
const isLast = step === steps.length - 1;

<ol className="steps">
  {steps.map((s, i) => (
    <li key={s.id} className={i < step ? "done" : i === step ? "now" : ""}>
      {s.title}
    </li>
  ))}
</ol>

{step > 0 && <button onClick={() => setStep(step - 1)}>Back</button>}
<button onClick={() => setStep(step + 1)}>{isLast ? "Submit" : "Next"}</button>

L3 One shared data object

Every input is controlled by the same bag, so Back keeps what you typed. One handler for all fields.

const [data, setData] = useState({ email:"", password:"", name:"", age:"" });

function handleChange(e){
  const { name, value } = e.target;              // name="email" → data.email
  setData(d => ({ ...d, [name]: value }));       // copy, then overwrite one key
}

<input name="email" value={data.email} onChange={handleChange} />
<input name="name"  value={data.name}  onChange={handleChange} />
Demo it Type, hit Next, hit Back — the text is still there. That's the answer to the question.

L4 Per-step validate + gated errors

Each step owns a validate(data) that returns an errors object. Next runs it.

const steps = [
  { id:"account", title:"Account", validate: d => ({
      ...(!d.email.includes("@") && { email:"Enter a valid email" }),
      ...(d.password.length < 8  && { password:"8 characters minimum" }),
  })},
  // ...profile, plan
];

function next(){
  const errs = steps[step].validate(data);
  setErrors(errs);
  setTried(true);                               // now errors are allowed to show
  if (Object.keys(errs).length) return;         // blocked
  setTried(false);
  setStep(s => s + 1);
}

{tried && errors.email && <p className="err">{errors.email}</p>}

tried is why you don't scream "invalid email" at someone who has typed the letter a.

The whole thing

const steps = [
  { id:"account", title:"Account",
    fields:[["email","Email"],["password","Password"]],
    validate: d => ({
      ...(!d.email.includes("@") && { email:"Enter a valid email" }),
      ...(d.password.length < 8  && { password:"8 characters minimum" }) }) },
  { id:"profile", title:"Profile",
    fields:[["name","Full name"],["age","Age"]],
    validate: d => ({
      ...(!d.name.trim() && { name:"Required" }),
      ...(Number(d.age) < 18 && { age:"Must be 18 or older" }) }) },
  { id:"plan", title:"Plan", fields:[["plan","Plan"]], validate: () => ({}) },
];

export default function Wizard(){
  const [step, setStep]     = useState(0);
  const [data, setData]     = useState({ email:"", password:"", name:"", age:"", plan:"free" });
  const [errors, setErrors] = useState({});
  const [tried, setTried]   = useState(false);

  const current = steps[step];
  const isLast  = step === steps.length - 1;

  const handleChange = e =>
    setData(d => ({ ...d, [e.target.name]: e.target.value }));

  function go(){
    const errs = current.validate(data);
    setErrors(errs); setTried(true);
    if (Object.keys(errs).length) return;
    if (isLast) return submit(data);
    setTried(false); setStep(s => s + 1);
  }

  return (
    <form onSubmit={e => { e.preventDefault(); go(); }}>
      <ol className="steps">
        {steps.map((s,i) => (
          <li key={s.id} className={i < step ? "done" : i === step ? "now" : ""}>
            {s.title}
          </li>))}
      </ol>

      {current.fields.map(([name,label]) => (
        <div key={name}>
          <label htmlFor={name}>{label}</label>
          <input id={name} name={name} value={data[name]}
                 onChange={handleChange}
                 aria-invalid={tried && !!errors[name]}
                 aria-describedby={`${name}-err`} />
          {tried && errors[name] &&
            <p id={`${name}-err`} className="err">{errors[name]}</p>}
        </div>))}

      {step > 0 && <button type="button" onClick={() => setStep(s => s - 1)}>Back</button>}
      <button type="submit">{isLast ? "Submit" : "Next"}</button>
    </form>
  );
}

Gotchas

State per step (step1Data, step2Data). Now Back and Submit both have to stitch three objects together. One data bag, always.
Rendering steps as three components that each own their inputs. Unmounting on step change wipes the values. Lift the data; the step is just a view.
Validating on every keystroke. "Invalid email" after one character feels hostile. Gate on tried (or per-field touched).
Mutating: data[name] = value; setData(data). Same object reference → React skips the re-render. Always spread a new object.
Forgetting e.preventDefault(). Enter inside a form reloads the page and you lose everything mid-demo.

If they push

"Add a review step before submit." It's a step with no fields and no validation — just render Object.entries(data) as a summary list, each row with an Edit button that calls setStep(i). Free, because everything is already in one object.
"Now actually submit it." Add status, not three booleans. 
const [status, setStatus] = useState("idle"); // idle | sending | error | done

async function submit(){
  setStatus("sending");
  try { await api.signup(data); setStatus("done"); }
  catch { setStatus("error"); }                // data still intact — user can retry
}
<button disabled={status === "sending"}>{status === "sending" ? "Submitting…" : "Submit"}</button>
"Keep the step in the URL." Read it instead of storing it: const step = Number(searchParams.get("step") ?? 0), and setSearchParams to move. Refresh keeps the step — but not the data, so mention that trade-off (sessionStorage if they care).
"Fields depend on earlier answers." Make steps a function of data: const steps = buildSteps(data). Skipped steps just aren't in the array, so the dots update for free.
"Would you use a library?" In real code, yes: react-hook-form for uncontrolled inputs (fewer re-renders, touched/dirty built in) and Zod for the schema — one schema.pick() per step replaces the hand-written validate. In an interview, say that, then hand-roll it anyway.

Say this out loud

  • "Two pieces of state: which step, and one object with every answer."
  • "The data lives in the parent, so going Back can't lose it — that's the point of the question."
  • "One steps array drives the progress dots and the rendered fields, so they can't drift apart."
  • "Each step carries its own validate, so validation scales with the config, not with if-statements."
  • "I won't show errors until they press Next — nagging on the first keystroke is bad UX."
  • "Inputs get a label, aria-invalid and aria-describedby so the error is announced, not just red."
  • "If this were production I'd reach for react-hook-form and a Zod schema per step."
