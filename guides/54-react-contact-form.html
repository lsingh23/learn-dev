54. Contact Form & Validation

Controlled inputs, one state object, one pure validator. The most-asked form question.

The ask

Interviewer "Build a contact form with name, email and message. Show inline errors, and don't let an invalid form submit."

Three inputs, one validator, error text under the bad fields.

What we're building

Contact form — email field in its error state
Ada Lovelace
ada@
⚠ Enter a valid email
↑ red ring = aria-invalid · text = role="alert", linked by aria-describedby
Hi there…
Send disabled while submitting

Error only appears after blur or after a submit attempt — never while typing letter one.

It should:

  • Keep every value in React state
  • Show errors after blur, not while typing
  • Block submit and focus first bad field
  • Disable the button while submitting
  • Show a success or server-error message
  • Be usable with a screen reader

Styling barely matters here. Logic and accessibility are what's scored.

The mental model

Controlled = the input's value comes from state, and onChange writes it back. React is the source of truth; the DOM just mirrors it.

The trick

One values object, not three useStates. Give each input a name, and one handler covers all of them via e.target.name.

The shape of the state

const [values, setValues]   = useState({ name:'', email:'', message:'' }); // what's typed
const [touched, setTouched] = useState({});      // fields the user has left → may show errors
const [submitting, setSubmitting] = useState(false); // blocks double submit
const [status, setStatus]   = useState(null);    // 'ok' | 'error' | null (server outcome)

const errors = validate(values);                 // DERIVED — never stored in state

Rule of thumb: errors are a pure function of values, so compute them on render. Storing them gives you two sources of truth that drift apart.

Build it in layers

In an interview, build L1 and L2 first, out loud, then ask "want me to add validation and a11y?"

L1 Static markup, no state

The dumbest thing that renders. Labels wired with htmlFor from the start.

<form>
  <label htmlFor="name">Name</label>
  <input id="name" name="name" />
  /* email, message the same */
  <button>Send</button>
</form>

L2 Controlled: one object, one handler

Every input now reads from and writes to values.

const handleChange = (e) =>
  setValues(v => ({ ...v, [e.target.name]: e.target.value }));

<input id="name" name="name" value={values.name} onChange={handleChange} />
<input id="email" name="email" value={values.email} onChange={handleChange} />

L3 A pure validate() + touched

validate takes values, returns an errors object. No React inside — trivial to unit test, and reusable on submit.

function validate(v){
  const e = {};
  if (!v.name.trim()) e.name = 'Name is required';
  if (!/^\S+@\S+\.\S+$/.test(v.email)) e.email = 'Enter a valid email';
  if (v.message.trim().length < 10) e.message = 'Min 10 characters';
  return e;                         // → { email: 'Enter a valid email' }
}

const handleBlur = (e) => setTouched(t => ({ ...t, [e.target.name]: true }));
const show = (f) => touched[f] && errors[f];   // show only after blur

L4 Submit: block, focus, disable, report

Mark everything touched so all errors appear at once, then jump to the first bad field.

async function handleSubmit(e){
  e.preventDefault();
  setTouched({ name:true, email:true, message:true });
  const errs = validate(values);
  if (Object.keys(errs).length){
    document.getElementById(Object.keys(errs)[0])?.focus();   // first bad field
    return;
  }
  setSubmitting(true);
  try { await send(values); setStatus('ok'); setValues({name:'',email:'',message:''}); }
  catch { setStatus('error'); }
  finally { setSubmitting(false); }
}

The whole thing

function validate(v){
  const e = {};
  if (!v.name.trim()) e.name = 'Name is required';
  if (!/^\S+@\S+\.\S+$/.test(v.email)) e.email = 'Enter a valid email';
  if (v.message.trim().length < 10) e.message = 'Min 10 characters';
  return e;
}

const FIELDS = [['name','Name','input'],['email','Email','input'],['message','Message','textarea']];

export default function ContactForm({ send }){
  const [values, setValues] = useState({ name:'', email:'', message:'' });
  const [touched, setTouched] = useState({});
  const [submitting, setSubmitting] = useState(false);
  const [status, setStatus] = useState(null);
  const errors = validate(values);

  const change = (e) => setValues(v => ({ ...v, [e.target.name]: e.target.value }));
  const blur   = (e) => setTouched(t => ({ ...t, [e.target.name]: true }));

  async function onSubmit(e){
    e.preventDefault();
    setTouched({ name:true, email:true, message:true });
    const errs = validate(values);
    if (Object.keys(errs).length){
      document.getElementById(Object.keys(errs)[0])?.focus();
      return;
    }
    setSubmitting(true); setStatus(null);
    try { await send(values); setStatus('ok'); setValues({name:'',email:'',message:''}); setTouched({}); }
    catch { setStatus('error'); }
    finally { setSubmitting(false); }
  }

  return (
    <form onSubmit={onSubmit} noValidate>
      {FIELDS.map(([name, label, Tag]) => {
        const bad = touched[name] && errors[name];
        return (
          <div key={name}>
            <label htmlFor={name}>{label}</label>
            <Tag
              id={name} name={name} value={values[name]}
              onChange={change} onBlur={blur}
              aria-invalid={bad ? true : undefined}
              aria-describedby={bad ? `${name}-err` : undefined}
            />
            {bad && <p id={`${name}-err`} role="alert">{errors[name]}</p>}
          </div>
        );
      })}
      <button disabled={submitting}>{submitting ? 'Sending…' : 'Send'}</button>
      {status === 'ok'    && <p role="status">Thanks — we'll be in touch.</p>}
      {status === 'error' && <p role="alert">Something went wrong. Try again.</p>}
    </form>
  );
}

Gotchas

Errors shown while typing. "Email is required" on keystroke one is the classic ding. Gate every error on touched[field], or on a submit attempt.
value={x} with no onChange. React warns and the input is read-only. Either wire both, or use defaultValue for an uncontrolled field.
Missing e.preventDefault(). The page reloads and your state is gone. Also add noValidate so the browser's own bubbles don't fight your UI.
Storing errors in state. Now values and errors can disagree. Derive errors on every render instead.
Button not disabled. A double-click sends two emails. Guard with submitting, and reset it in finally.

If they push

"Disable the button until the form is valid." Don't — a disabled button with no explanation is a dead end for screen readers. Keep it enabled, validate on submit, and focus the first error.
"Check the username isn't taken." Async validation, debounced so you don't hit the API per keystroke. Keep the result in its own state and ignore stale responses. 
useEffect(() => {
  if (!values.username) return;
  const id = setTimeout(async () => {
    const taken = await api.check(values.username);   // 400ms after they stop
    setAsyncErr(taken ? 'Username taken' : null);
  }, 400);
  return () => clearTimeout(id);        // cancel on next keystroke
}, [values.username]);
"Use a schema instead of hand-rolled ifs." Zod: declare the shape once, get types and messages for free. 
const schema = z.object({
  name: z.string().min(1, 'Name is required'),
  email: z.string().email('Enter a valid email'),
  message: z.string().min(10, 'Min 10 characters'),
});
// flatten() gives you { email: ['Enter a valid email'] }
const errors = schema.safeParse(values).error?.flatten().fieldErrors ?? {};
"Why is react-hook-form faster?" It keeps values in refs (a ref — a box that survives re-renders) and registers inputs as uncontrolled, so typing doesn't re-render the form. Only the field whose error changed re-renders. Worth it at ~15+ fields.
"1000 fields / a giant form." Split into sections, each its own component with its own state slice, so a keystroke re-renders one section. Or go uncontrolled with FormData(e.currentTarget) on submit.

Say this out loud

  • "I'll keep one values object rather than a useState per field, so one handler covers all three via e.target.name."
  • "validate is pure — values in, errors out — so it's easy to test and I can call the same function on submit."
  • "Errors are derived, not stored, so they can't drift out of sync with the values."
  • "I only show an error once the field is touched — nagging someone on their first keystroke is bad UX."
  • "Every input has a label with htmlFor, plus aria-invalid and aria-describedby pointing at the error, which is role=\"alert\"."
  • "On submit I preventDefault, mark everything touched, and focus the first invalid field so keyboard users land in the right place."
  • "The button is disabled while submitting so a double-click can't send twice."
